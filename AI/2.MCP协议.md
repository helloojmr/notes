## MCP 是什么

- **MCP**（Model Context Protocol，模型上下文协议）：**AI 应用与外部工具、数据源之间的开放连接协议**，Anthropic 2024 年提出，2025 年移交 Linux 基金会托管。
- **定位**：AI 时代的"协议层"基础设施——类比 USB-C（统一插拔）和 LSP（语言服务器协议，统一 IDE 与语言工具对接）。
- **解决的核心矛盾**：模型有推理能力但无执行能力、无实时数据；工具遍地但接入方式各自为政。
- **一句话**：定义"模型 ↔ 工具"之间如何发现能力、调用能力、传递结果的标准，让工具写一次、处处可用。

### 为什么需要 MCP

- **LLM 的信息孤岛**：模型知识截止于训练时间，拿不到实时数据（数据库、API、文件、日志）。
- **工具接入混乱**：没有标准前，每个 AI 应用对接每个工具都要定制开发，重复造轮子。
- **安全受控**：AI 调用工具需要授权边界（谁允许调、能调什么、结果怎么用、全程可审计）。
- **生态复用**：一个 MCP Server 写一次，可在多个支持 MCP 的客户端（IDE、聊天助手、自动化平台）直接复用。
- **测试自动化价值**：AI 要"发请求、跑用例、查日志、读数据库"都通过 MCP 接（接数据库 MCP 造数验数、接日志 MCP 排查报错、接接口/压测 MCP 触发回归看报告），不用为每个 AI 定制。

## 架构与核心概念

### 架构与角色

- **Host（宿主）**：运行 AI 应用的程序（IDE、聊天客户端、自动化平台），管理多个连接、负责授权和调度。
- **Client（客户端）**：Host 内与单个 Server 一一对应的连接组件，负责握手、转发请求、处理响应。
- **Server（服务端）**：暴露具体能力的独立进程，轻量、专注、无 UI（查库、操作浏览器、读文件）。
- **三者关系**：一个 Host 可有多个 Client，一个 Client 连一个 Server；模型在 Host 里，通过 Client 调 Server 的工具。

### 三类能力（Server 暴露什么）

- **Tool（工具）**：**可执行的动作**——建订单、发请求、写文件，**有副作用**，由模型按需调用。
- **Resource（资源）**：**只读数据**——查订单、读文件内容，**无副作用**，按 URI 读取。
- **Prompt（提示模板）**：**可复用的指令模板**——"你是订单助手，回答要简洁"，规范模型怎么用工具。
- **选型经验**：能做成 Resource 就优先 Resource（更安全），必须执行动作才做成 Tool；Prompt 用于固定使用方式。

### 协议工作机制（MCP 怎么工作）

- **传输层**：基于 JSON-RPC 2.0；本地进程走 **stdio**（命令行管道），远程走 **Streamable HTTP**（单 POST 端点，一个请求一次 POST）——旧版 HTTP+SSE 已废弃。
- **连接建立（能力协商）**：客户端与服务端交换协议版本和"我支持什么"（工具/资源/模板），能力不匹配的请求不会发出——向后兼容的关键。
- **核心方法**：
  - 工具：`tools/list`（发现）→ `tools/call`（调用）。
  - 资源：`resources/list` / `resources/read`（发现与读取）。
  - 模板：`prompts/list` / `prompts/get`。
- **一次调用流程**：
  1. 客户端启动时向 Server 拉取能力清单。
  2. 模型根据任务判断该用哪个工具，向客户端发起调用请求。
  3. 客户端把请求发给对应 Server，Server 执行并返回结果。
  4. 模型拿着结果继续推理，最终回复用户。
- **人机交互**：Server 执行中需要用户输入（确认、补参数）时，返回"需要输入"标记 + 待回答的问题，客户端收集答案后重试原请求——无状态场景下的人机协作。
- **变更通知**：工具/资源清单变化时，Server 通过订阅流通知客户端刷新。

## 主流 SDK 与框架

- **官方 Tier 1 SDK**：TypeScript、Python、Go、C#（四个一等公民，Rust 跟进中），同时支持写 Server 和 Client。
- **Python 主流框架：FastMCP**——官方 Python SDK 的轻量封装，装饰器写工具/资源/模板，是目前社区最常用的上手方式。
- **TypeScript SDK v2**：拆分为 `@modelcontextprotocol/server` + `@modelcontextprotocol/client` 两个包；HTTP 部署用 `createMcpHandler`，一个端点同时兼容新旧协议版本。
- **生态现状**：MCP 已是主流 AI 编码工具的事实标准，各大云厂商（AWS Bedrock AgentCore 等）原生支持。

## 从零实现一个 Server（Python + FastMCP）


### 环境


#### 说明
- Python 3.10+，`pip install fastmcp`。

### 项目结构

```
my-mcp-server/
├── server.py           主程序：定义工具/资源/模板
├── requirements.txt    依赖
└── README.md           说明 Server 暴露了哪些能力
```

### 完整代码（订单查询 Server）

```
from fastmcp import FastMCP
import sqlite3, json

mcp = FastMCP("order-server")

# ---- Tool：可执行动作（有副作用）----
@mcp.tool()
def create_order(user_id: int, goods_id: int, num: int) -> str:
    """创建订单，返回订单号"""
    conn = sqlite3.connect("orders.db")
    cur = conn.cursor()
    cur.execute("INSERT INTO orders(user_id, goods_id, num) VALUES(?,?,?)",
                (user_id, goods_id, num))
    conn.commit()
    order_id = cur.lastrowid
    conn.close()
    return json.dumps({"order_id": order_id})

# ---- Resource：只读数据（无副作用）----
@mcp.resource("orders://{order_id}")
def get_order(order_id: str) -> str:
    """查询订单详情"""
    conn = sqlite3.connect("orders.db")
    row = conn.execute("SELECT * FROM orders WHERE id=?", (order_id,)).fetchone()
    conn.close()
    return json.dumps({"order": row}, ensure_ascii=False)

# ---- Prompt：可复用模板 ----
@mcp.prompt()
def order_expert() -> str:
    """订单助手人格设定"""
    return "你是订单查询助手，用 get_order 查订单，用 create_order 建单，回答要简洁。"

if __name__ == "__main__":
    mcp.run()   # 默认 stdio 传输
```

## 安全模型与生态

### 安全模型

- **用户授权**：工具调用权在用户/宿主手里，模型只是"建议调用"，Host 可拦截、确认、审计。
- **信任边界**：每个 Server 独立进程、最小权限运行；文件类 Server 限定可访问根目录。
- **工具白名单**：Host 侧配置哪些 Server/Tool 可用，不是所有工具对模型开放。
- **危险操作确认**：写操作、支付类工具要求 Host 弹确认，模型不能静默执行。
- **远程部署**：校验 Origin 头（防 DNS rebinding）、只绑 localhost 本地调试、OAuth 鉴权、敏感数据脱敏。
- **上线前按接口标准测**：鉴权、超时、并发、参数校验、敏感数据脱敏、审计——MCP Server 是一个新的被测对象。

### 生态

- **主流客户端**：Claude Desktop/Code、Cursor、VS Code Copilot、Cline、Continue、OpenCode 等。
- **注册表**：官方 Registry + 社区站（mcp.so、Smithery 等），数千个现成 Server（数据库、浏览器、邮件、支付、监控）。
- **测试工具链**：数据库 MCP、日志 MCP、接口/压测工具 MCP 陆续出现，AI 测试工具链在成型。
- **排查套路**（三层法，和排查接口一致）：Server 是否启动（看日志）→ 传输是否通（stdio/URL/鉴权）→ 能力与权限（能力协商是否成功、工具是否在列表、Host 是否放行）。

## 面试高频题

- **Q**：MCP 是什么？解决什么问题？**A**：AI 应用连接外部工具/数据的标准协议，解决模型拿不到实时数据、工具接入不统一的问题。
- **Q**：MCP 的核心组件？**A**：Host（宿主）、Client、Server，以及 Tool（执行动作）、Resource（读数据）、Prompt（模板）三类能力。
- **Q**：Tool 和 Resource 的区别？**A**：Tool 有副作用（执行动作），Resource 只读（取数据）；能只读就优先 Resource。
- **Q**：本地和远程传输怎么选？**A**：本地进程用 stdio（简单安全）；跨机器/多客户端用 Streamable HTTP（需鉴权、可扩展）。
- **Q**：MCP 安全上怎么防模型乱调工具？**A**：用户/宿主授权、工具白名单、限定访问范围、危险操作弹确认、审计日志。
- **Q**：MCP Server 上线前要测什么？**A**：鉴权、超时、并发、参数校验、脱敏、审计——当接口测。
