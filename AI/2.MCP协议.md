## MCP 是什么

- **MCP**（Model Context Protocol，模型上下文协议）：AI 应用与外部工具/数据源之间的开放连接协议，Anthropic 2024 年提出，2025 年捐给 Linux 基金会托管。
- **定位**：AI 时代的"协议层"基础设施——统一"AI 如何接工具"，类比 USB-C / LSP。
- **一句话**：定义"模型 ↔ 工具"之间如何发现能力、调用能力、传递结果的标准。

## 协议现状（2026-07-28 稳定版）

- MCP 规范用日期版本号，各版本差异大，实现必须声明自己所遵循的版本。
- **2026-07-28 是当前最新稳定版**，核心改动如下（理解这些才算懂当今 MCP）。

### 核心变化：无状态化

- 移除 `initialize` 握手和 protocol sessions——**每次请求自带协议版本和能力元数据**。
- 新增必选的 `server/discover` 方法。
- 好处：服务端可以部署在无状态、可水平扩展的普通 HTTP 基础设施上（网关/负载均衡友好）。

### 传输：Streamable HTTP（唯一远程传输）

- **HTTP+SSE 传输已正式废弃**（一年过渡期），远程统一用 Streamable HTTP。
- 服务端暴露**单个 POST 端点**（如 `https://example.com/mcp`），客户端每个 JSON-RPC 请求单独发一个 POST。
- 响应可以是单个 JSON 对象，或该请求作用域内的 SSE 流（进度通知 + 最终响应）。
- 安全要求：服务端必须校验 `Origin` 头（防 DNS rebinding），本地运行只绑 localhost。

### 服务端交互：MRTR（多轮往返请求）

- 服务端需要用户输入时（确认、补参数），**不再主动发请求**，而是返回 `resultType: "input_required"` + `inputRequests`。
- 客户端收集答案后带 `inputResponses` **重试原请求**——无状态协议下的人机交互方案。

### 变更通知：subscriptions/listen

- 取代旧版 HTTP GET stream 和 `resources/subscribe`。
- 客户端发 `subscriptions/listen` 开一条长连接流，按需订阅 `tools/list_changed`、`resources/updated` 等通知类型。

### 已废弃项（新实现不要采用）

- **Roots、Sampling、Logging 已废弃**（至少 12 个月兼容期，新实现不应采用）。
- **Tasks 移出核心**，变成官方扩展 `io.modelcontextprotocol/tasks`（AWS 贡献，poll 式 `tasks/get` + `tasks/update`）。
- 工具列表/资源列表响应带 `ttlMs` + `cacheScope` 缓存提示（可缓存，减少重复拉取）。

## 主流 SDK 与框架

- **官方 Tier 1 SDK（4 个）**：TypeScript、Python、Go、C#，全部支持 2026-07-28 规范（Rust 在 beta）。
- **TS SDK v2**：拆分为 `@modelcontextprotocol/server` + `@modelcontextprotocol/client`；HTTP 部署入口 `createMcpHandler`，一个端点同时兼容新旧协议版本。
- **Python 主流框架：FastMCP**（社区最常用，基于官方 Python SDK 封装），当前 v1 API（`@mcp.tool()` 装饰器），一个 HTTP 端点可同时应答新旧协议。
- **v1 → v2 迁移**：TS 主要变化 `.tool()` → `registerTool`、错误类型改名，官方提供 codemod 一键迁移。


### 完整代码（订单查询 Server）

```
from fastmcp import FastMCP
import sqlite3, json

mcp = FastMCP("order-server")

# ---- Tool：可执行动作（有副作用）----
@mcp.tool()
def create_order(user_id: int, goods_id: int, num: int) -> str:
    """创建订单，返回订单号"""
    conn = sqlite3.connect("orders.db")
    cur = conn.cursor()
    cur.execute("INSERT INTO orders(user_id, goods_id, num) VALUES(?,?,?)",
                (user_id, goods_id, num))
    conn.commit()
    order_id = cur.lastrowid
    conn.close()
    return json.dumps({"order_id": order_id})

# ---- Resource：只读数据（无副作用）----
@mcp.resource("orders://{order_id}")
def get_order(order_id: str) -> str:
    """查询订单详情"""
    conn = sqlite3.connect("orders.db")
    row = conn.execute("SELECT * FROM orders WHERE id=?", (order_id,)).fetchone()
    conn.close()
    return json.dumps({"order": row}, ensure_ascii=False)

# ---- Prompt：可复用模板 ----
@mcp.prompt()
def order_expert() -> str:
    """订单助手人格设定"""
    return "你是订单查询助手，用 get_order 查订单，用 create_order 建单，回答要简洁。"

if __name__ == "__main__":
    mcp.run()   # 默认 stdio 传输
```

## 生态与安全

- **注册表**：官方 Registry + 社区站（mcp.so、Smithery），数千个 Server。
- **主流客户端**：Claude Desktop/Code、Cursor、VS Code Copilot、Cline、Continue、OpenCode 等。
- **安全要点（按官方规范）**：
  - 远程 Server 必须校验 `Origin` 头，防 DNS rebinding。
  - 本地运行只绑 `127.0.0.1`，不绑 `0.0.0.0`。
  - 认证用 OAuth 2.1 框架；工具标注 read-only / destructive / idempotent 供宿主决策。
  - 工具调用权在宿主手里，模型只是"建议调用"。

## 测开视角

- **AI 测试平台的基础设施**：AI 要"发请求、跑用例、查日志、读数据库"，都通过 MCP 接。
- **让 AI 干活的具体姿势**：接数据库 MCP（读测试数据/造数/验数）、接日志 MCP（排查报错）、接接口 MCP（触发回归看报告）。
- **测试重点**：鉴权、超时、并发、参数校验、脱敏、审计——MCP Server 是一个新的被测对象。
- **协议版本注意**：对接前确认双方协议的日期版本（2026-07-28 vs 旧版），能力差异大。

## 面试高频题

- **Q**：MCP 的三类核心能力？**A**：Tool（可执行动作）、Resource（只读数据）、Prompt（模板），分别对应执行、读取、引导。
- **Q**：MCP 当前主流传输是什么？**A**：本地 stdio、远程 Streamable HTTP（单 POST 端点）；HTTP+SSE 已废弃。
- **Q**：2026-07-28 规范最大的变化？**A**：核心无状态化（移除 initialize/sessions，请求自带版本元数据）、MRTR 取代服务端主动请求、subscriptions/listen 取代订阅。
- **Q**：MCP Server 上线前要测什么？**A**：鉴权、超时、并发、参数校验、脱敏、审计——当接口测。
- **Q**：哪些能力被废弃了？**A**：Roots、Sampling、Logging、HTTP+SSE 传输；新实现不应采用。
