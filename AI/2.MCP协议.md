## MCP 是什么

- **MCP**（Model Context Protocol，模型上下文协议）：**AI 应用连接外部工具和数据源的标准协议**，Anthropic 2024 年提出，后捐给 Linux 基金会。
- **一句话**：让 AI 能"调用工具、读数据"的统一接口标准。
- **类比**：LLM 是大脑，MCP 就是大脑的"USB-C 接口"——工具做成标准插头，谁来都能插。

## 为什么需要

- **模型有推理、没数据**：LLM 只有训练时的知识，拿不到实时数据（数据库、API、文件、日志）。
- **工具接入杂乱**：每家 AI 对接工具的方式都不一样，重复造轮子。
- **统一之后的好处**：一个 MCP Server 写一次，Claude、Cursor、各种 AI 客户端都能用。

## 核心概念（白话版）

- **Host（宿主）**：跑 AI 应用的程序（IDE、聊天客户端）。
- **Client（客户端）**：Host 里负责跟 Server 通信的部分。
- **Server（服务端）**：实现具体能力的程序——查数据库、操作浏览器、读文件。
- **Tool（工具）**：**能执行动作**的能力（建订单、发请求），有副作用。
- **Resource（资源）**：**只读数据**（查订单、读文件），没副作用。
- **Prompt（提示模板）**：可复用的指令模板（"你是订单助手，回答要简洁"）。
- **怎么选**：能做成 Resource 就优先 Resource（安全），必须执行动作才做成 Tool。

## 工作方式（一次调用怎么发生的）

1. 客户端启动时问 Server："你有什么能力"（工具/资源清单）。
2. 模型判断该用哪个工具，向客户端发起调用。
3. 客户端把请求发给对应 Server，Server 执行并返回结果。
4. 模型拿着结果继续推理，最终回复用户。

## 怎么用（Python 示例，可抄）

### 安装

- `pip install fastmcp`

### 写一个 Server（订单查询）

```
from fastmcp import FastMCP
import sqlite3, json

mcp = FastMCP("order-server")

@mcp.tool()
def create_order(user_id: int, goods_id: int, num: int) -> str:
    """创建订单，返回订单号"""
    conn = sqlite3.connect("orders.db")
    cur = conn.cursor()
    cur.execute("INSERT INTO orders(user_id, goods_id, num) VALUES(?,?,?)",
                (user_id, goods_id, num))
    conn.commit()
    order_id = cur.lastrowid
    conn.close()
    return json.dumps({"order_id": order_id})

@mcp.resource("orders://{order_id}")
def get_order(order_id: str) -> str:
    """查询订单详情"""
    conn = sqlite3.connect("orders.db")
    row = conn.execute("SELECT * FROM orders WHERE id=?", (order_id,)).fetchone()
    conn.close()
    return json.dumps({"order": row}, ensure_ascii=False)

if __name__ == "__main__":
    mcp.run()   # 本地运行，默认 stdio 传输
```

### 客户端接入配置

- 在支持 MCP 的客户端（IDE、聊天应用）配置里加一段：

```
{
  "mcpServers": {
    "order-server": {
      "command": "python",
      "args": ["D:/my-mcp-server/server.py"]
    }
  }
}
```

#### 配置后效果

- 对话里说"查一下订单 1001"，模型自动调 `get_order` 返回结果。

## 使用方式与注意点

- **本地进程**：走 stdio（命令行管道），最简单安全。
- **远程服务**：走 HTTP（Streamable HTTP），跨机器、多客户端用，**要加鉴权**。
- **调试**：官方 MCP Inspector（`npx @modelcontextprotocol/inspector python server.py`），可视化看请求/响应。
- **协议版本**：MCP 规范在持续演进（2026 年有过大版本更新），对接时确认双方版本一致，避免能力不匹配。

## 测开视角

- **AI 测试平台的基础设施**：AI 要"发请求、跑用例、查日志、读数据库"，都通过 MCP 接，不用为每个 AI 定制。
- **让 AI 干活的具体姿势**：
  - 接数据库 MCP：AI 读测试数据、造数、验数。
  - 接日志 MCP：AI 排查失败用例的报错堆栈。
  - 接接口/压测 MCP：AI 触发回归、看报告。
- **MCP Server 本身要测**：鉴权、超时、并发、参数校验、敏感数据脱敏——当接口测。
- **安全底线**：工具调用权在用户/宿主手里，危险操作（写库、支付）要有确认；Server 最小权限运行。

## 面试高频题

- **Q**：MCP 是什么？解决什么问题？**A**：AI 应用连接外部工具/数据的标准协议，解决模型拿不到实时数据、工具接入不统一的问题。
- **Q**：MCP 的核心组件？**A**：Host（宿主）、Client、Server，以及 Tool（执行）、Resource（读数据）、Prompt（模板）三类能力。
- **Q**：Tool 和 Resource 的区别？**A**：Tool 有副作用（执行动作），Resource 只读（取数据）；能只读就优先 Resource。
- **Q**：MCP 对测试自动化有什么意义？**A**：让 AI 通过统一协议调用测试工具，是 AI 测试平台、AI 用例生成的基础设施。
