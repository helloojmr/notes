## MCP 是什么

- **MCP**（Model Context Protocol，模型上下文协议）：**AI 应用（模型）与外部工具/数据源之间的标准化连接协议**，由 Anthropic 于 2024 年提出并开源。
- **类比**：如果说 LLM 是"大脑"，MCP 就是"大脑的 USB-C 接口"——统一了插拔工具和数据的方式。
- **解决什么问题**：以前每个 AI 应用对接一个工具都要定制开发；MCP 让工具按统一协议接入，一处开发、处处可用。
- **一句话**：让 AI 能"调用工具、读数据"的行业标准协议。

## 为什么需要

- **LLM 的信息孤岛**：模型本身只有训练时的知识，拿不到实时数据（数据库、API、文件、搜索）。
- **工具调用混乱**：各家 AI 对接工具的方式不统一，重复造轮子。
- **安全与权限**：AI 调用工具需要受控（谁授权、能调什么、结果怎么用）。
- **生态互通**：一个 MCP Server 写一次，可在多个支持 MCP 的客户端（IDE、聊天助手、自动化平台）复用。

## 核心概念

- **Host（宿主）**：运行 AI 应用的程序（如 IDE、聊天客户端），负责调度。
- **Client（客户端）**：Host 内部的连接组件，负责与 Server 通信。
- **Server（服务端）**：暴露工具/资源的程序，实现具体能力（查数据库、操作浏览器等）。
- **Tool（工具）**：可被模型调用的函数式能力（如"查询订单"），有入参出参定义。
- **Resource（资源）**：可读的数据源（如文件内容、数据库记录），模型按需读取。
- **Prompt（提示模板）**：可复用的指令模板，规范模型如何用工具。
- **传输层**：基于 JSON-RPC 2.0，通过 stdio（本地进程）或 HTTP/SSE（远程服务）通信。

## 工作方式

1. 客户端启动时向 Server 请求能力清单（有哪些 Tool / Resource）。
2. 模型根据用户问题判断需要哪个工具，向客户端发起调用请求。
3. 客户端把请求发给对应 Server，Server 执行并返回结果。
4. 模型拿到结果继续推理，最终回复用户。

## 生态与常见 MCP

- **官方 Servers**：官方维护的参考实现（filesystem、github、fetch、sqlite 等）。
- **社区 Server**：数千个，覆盖数据库、浏览器、邮件、测试工具、支付等。
- **常用例子**：GitHub MCP（操作仓库）、文件系统 MCP（读写本地文件）、数据库 MCP（查库）、浏览器 MCP（自动化网页）。
- **测开相关**：JMeter/Postman 类 MCP、抓包工具 MCP、测试平台 MCP 陆续出现。

## 测开视角

- **AI 测试平台的基础设施**：让 AI 直接调用测试工具（发请求、跑用例、查日志），靠的就是 MCP 这类协议。
- **工具接入标准化**：公司自研测试工具包一个 MCP Server，整个 AI 工具链都能用，不再一对一定制。
- **AI 用例生成落地**：模型通过 MCP 读取接口文档/数据库 Schema，生成更准确的用例和测试数据。
- **调试思路**：MCP 连接不上先分三层查——Server 是否启动、传输是否通、权限是否够（和排查接口 3 层同理）。

## 面试高频题

- **Q**：MCP 是什么？解决什么问题？**A**：模型与外部工具/数据源的标准化连接协议，解决 LLM 信息孤岛和工具调用不统一。
- **Q**：MCP 的核心组件有哪些？**A**：Host、Client、Server，以及 Tool、Resource、Prompt 三类能力。
- **Q**：MCP 对测试自动化有什么意义？**A**：让 AI 通过统一协议调用测试工具，是 AI 测试平台、AI 用例生成的基础设施。
