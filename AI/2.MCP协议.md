## MCP 是什么

- **MCP**（Model Context Protocol，模型上下文协议）：**AI 应用与外部工具/数据源之间的开放连接协议**，Anthropic 2024 年提出，已捐给 Linux 基金会（2025 年 3 月，成立 Agentic AI 组织托管）。
- **定位**：AI 时代的"协议层"基础设施——类比 USB-C / LSP（语言服务器协议），统一"AI 如何接工具"。
- **设计动机**：模型有推理能力但无执行能力、无实时数据；工具遍地但接入方式各自为政。
- **一句话**：定义"模型 ↔ 工具"之间如何发现能力、调用能力、传递结果的标准。

## 协议层细节（懂协议才算懂 MCP）

- **传输**：基于 **JSON-RPC 2.0**；本地走 **stdio**（子进程管道），远程走 **Streamable HTTP / SSE**。
- **生命周期**：
  - `initialize`：客户端发协议版本 + 能力声明，服务端回其版本 + 能力，完成**能力协商**。
  - `initialized`：握手完成后通知服务端。
  - 之后按需收发请求/通知/响应。
- **核心方法**：
  - `tools/list`、`tools/call`：工具发现与调用。
  - `resources/list`、`resources/read`：资源发现与读取。
  - `prompts/get`：提示模板获取。
- **能力协商（capabilities）**：双方声明支持什么（tools? resources? prompts? logging? sampling?），不支持就不发对应请求——向后兼容的关键。
- **采样（sampling）**：服务端可反向请求客户端调用 LLM（服务端"请模型帮个忙"），用于工具内部需要模型推理的场景。
- **roots**：客户端向服务端声明"我允许你访问哪些根目录/作用域"，是权限表达机制。

## 架构与组件

- **Host**：运行 AI 应用的宿主（IDE、聊天客户端、自动化平台），管理多个 Client。
- **Client**：Host 内与单个 Server 的 1:1 连接，负责握手、请求转发。
- **Server**：暴露 Tool / Resource / Prompt 的进程，轻量、专注、无 UI。
- **Tool**：可调用的函数式能力——**有副作用**（写库、发请求），模型决定何时调用。
- **Resource**：只读数据——**无副作用**（读文件、查记录），模型按需取。
- **Prompt**：可复用指令模板，规范模型怎么用工具。
- **一条经验**：能做成 Resource 就优先 Resource（安全），必须执行动作才做成 Tool。

## 安全模型（面试加分点）

- **用户授权**：工具的调用权在用户/宿主手里，模型只是"建议调用"，Host 可拦截、确认、审计。
- **信任边界**：每个 Server 是独立进程，最小权限运行；文件类 Server 通过 roots 限定可访问范围。
- **Tool 白名单**：Host 侧配置哪些 Server/Tool 可用，不是所有工具对模型开放。
- **危险操作确认**：写操作、支付类工具通常要求 Host 弹确认，模型不能静默执行。
- **测开视角**：接入 MCP 工具链时，第一件事是列"工具清单 + 权限矩阵"，跟接口权限设计一个思路。

## 服务端实现（Python 示例：查数据库的 Server）

```
from mcp.server.fastmcp import FastMCP
import sqlite3

mcp = FastMCP("order-db")

@mcp.tool()
def query_order(order_id: int) -> str:
    """按订单号查订单，返回 JSON 字符串"""
    conn = sqlite3.connect("orders.db")
    row = conn.execute(
        "SELECT * FROM orders WHERE id = ?", (order_id,)
    ).fetchone()
    conn.close()
    return str(row)

if __name__ == "__main__":
    mcp.run()          # 默认 stdio 传输
```

#### 运行与要点

- 客户端连上后，模型就能通过 `query_order` 查订单，无需任何定制对接。
- 生产环境注意：加超时、并发限制、参数校验、审计日志——**工具即接口**，要按接口标准做。

## 生态与调试

- **官方 Servers**：filesystem、github、fetch、sqlite、time 等参考实现。
- **社区**：数千个 Server，覆盖数据库、浏览器、邮件、支付、监控。
- **调试工具**：**MCP Inspector**（官方调试台，可视化看握手/请求/响应）、服务端日志、`mcp` CLI。
- **排查套路**（三层法，和排查接口一致）：
  1. Server 是否启动、进程是否存活（看日志）。
  2. 传输是否通（stdio 看启动参数、远程看 URL/鉴权）。
  3. 能力与权限（initialize 是否成功、工具是否在列表、Host 是否放行）。

## 测开视角

- **AI 测试平台的基础设施**：AI 要"发请求、跑用例、查日志、读数据库"，都通过 MCP 这类协议接，不再为每个 AI 定制。
- **让 AI 干活的具体姿势**：
  - 接数据库 MCP：AI 读测试数据、造数、验数。
  - 接日志 MCP：AI 排查失败用例的报错堆栈。
  - 接接口/压测 MCP：AI 触发回归、看报告。
- **企业落地步骤**：盘点工具 → 按最小权限包 Server → 配 Host 白名单 → 加审计 → 灰度开放。
- **测试重点**：Server 的鉴权、超时、并发、参数校验、敏感数据脱敏——MCP Server 就是一个新的被测对象。

## 面试高频题

- **Q**：MCP 的三类核心能力是什么？**A**：Tool（可调用动作）、Resource（只读数据）、Prompt（模板），分别对应执行、读取、引导。
- **Q**：MCP 安全上怎么防模型乱调工具？**A**：用户/宿主授权、Tool 白名单、roots 限范围、危险操作弹确认、审计日志。
- **Q**：stdio 和远程传输怎么选？**A**：本地进程用 stdio（简单安全）；跨机器/多客户端用 Streamable HTTP（需鉴权、可扩展）。
- **Q**：MCP Server 上线前要测什么？**A**：鉴权、超时、并发、参数校验、脱敏、审计——当接口测。
