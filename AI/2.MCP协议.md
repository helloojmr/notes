## MCP 是什么

- **MCP**（Model Context Protocol，模型上下文协议）：**AI 应用与外部工具/数据源之间的开放连接协议**，Anthropic 2024 年提出，2025 年捐给 Linux 基金会托管。
- **定位**：AI 时代的"协议层"基础设施——统一"AI 如何接工具"，类比 USB-C / LSP。
- **一句话**：定义"模型 ↔ 工具"之间如何发现能力、调用能力、传递结果的标准。

## 协议层细节（懂协议才算懂 MCP）

- **传输**：基于 **JSON-RPC 2.0**；本地走 **stdio**（子进程管道），远程走 **Streamable HTTP / SSE**。
- **生命周期**：
  - `initialize`：客户端发协议版本 + 能力声明，服务端回版本 + 能力，完成**能力协商**。
  - `initialized`：握手完成通知。
  - 之后按需收发请求/通知/响应。
- **核心方法**：`tools/list`、`tools/call`（工具）；`resources/list`、`resources/read`（资源）；`prompts/get`（模板）。
- **能力协商**：双方声明支持什么，不支持就不发对应请求——向后兼容的关键。
- **sampling**：服务端可反向请求客户端调 LLM（服务端"请模型帮个忙"）。
- **roots**：客户端向服务端声明"允许访问哪些根目录"，是权限表达机制。

## 架构与组件

- **Host**：运行 AI 应用的宿主（IDE、聊天客户端、自动化平台）。
- **Client**：Host 内与单个 Server 的 1:1 连接。
- **Server**：暴露 Tool / Resource / Prompt 的进程，轻量、专注、无 UI。
- **Tool**：可调用的动作，**有副作用**（写库、发请求）。
- **Resource**：只读数据，**无副作用**（读文件、查记录）。
- **Prompt**：可复用指令模板。
- **经验**：能做成 Resource 优先 Resource（安全），必须执行动作才做成 Tool。

## 安全模型

- **用户授权**：工具调用权在用户/宿主手里，模型只是"建议调用"，Host 可拦截/确认/审计。
- **信任边界**：每个 Server 独立进程、最小权限运行；文件类 Server 用 roots 限范围。
- **Tool 白名单**：Host 侧配置哪些 Server/Tool 可用。
- **危险操作确认**：写操作、支付类工具要求 Host 弹确认。
- **测开视角**：接入工具链第一件事 = 列"工具清单 + 权限矩阵"。

## 从零写一个 MCP Server（实操）

### 环境准备

#### 安装 SDK

```
pip install fastmcp
```

### 项目结构

```
my-mcp-server/
├── server.py           主程序：定义工具/资源/模板
├── requirements.txt    依赖
└── README.md           说明这个 Server 暴露了哪些能力
```

### 完整代码（一个"订单查询"Server）

```
from fastmcp import FastMCP
import sqlite3, json

mcp = FastMCP("order-server")

# ---- Tool：可执行动作（有副作用）----
@mcp.tool()
def create_order(user_id: int, goods_id: int, num: int) -> str:
    """创建订单，返回订单号"""
    conn = sqlite3.connect("orders.db")
    cur = conn.cursor()
    cur.execute("INSERT INTO orders(user_id, goods_id, num) VALUES(?,?,?)",
                (user_id, goods_id, num))
    conn.commit()
    order_id = cur.lastrowid
    conn.close()
    return json.dumps({"order_id": order_id})

# ---- Resource：只读数据（无副作用）----
@mcp.resource("orders://{order_id}")
def get_order(order_id: str) -> str:
    """查询订单详情"""
    conn = sqlite3.connect("orders.db")
    row = conn.execute("SELECT * FROM orders WHERE id=?", (order_id,)).fetchone()
    conn.close()
    return json.dumps({"order": row}, ensure_ascii=False)

# ---- Prompt：可复用模板 ----
@mcp.prompt()
def order_expert() -> str:
    """订单助手人格设定"""
    return "你是订单查询助手，用 get_order 查订单，用 create_order 建单，回答要简洁。"

if __name__ == "__main__":
    mcp.run()   # 默认 stdio 传输
```

### 本地调试（连上就能玩）

- 直接运行 `python server.py`，FastMCP 会进入 stdio 监听，等客户端连接。

#### MCP Inspector 调试

```
npx @modelcontextprotocol/inspector python server.py
```

#### Inspector 能看什么

- initialize 握手、工具列表、调用 create_order 的请求/响应——排查和看接口文档一样。

### 客户端接入配置

- 在支持 MCP 的客户端（IDE、聊天应用）里加一个 Server 配置，指定启动命令：

#### 配置示例

```
{
  "mcpServers": {
    "order-server": {
      "command": "python",
      "args": ["D:/my-mcp-server/server.py"]
    }
  }
}
```

#### 配置后效果

- 对话里直接说"查一下订单 1001"，模型自动调 `get_order` 返回结果。
- 远程部署：把 `command/args` 换成 `"url": "https://your-server/mcp"`（HTTP 传输，需鉴权）。

### 上线前检查清单

- 参数校验：非法输入要报错，不能把脏数据写进库。
- 超时与并发：工具调用要有超时上限、并发限制（工具即接口）。
- 审计日志：谁调了什么工具、参数是什么。
- 敏感数据脱敏：返回给模型的数据不能带密码/密钥。
- 权限：Server 进程用最小权限账号跑，数据库账号只给所需表权限。

## 生态与调试

- **官方 Servers**：filesystem、github、fetch、sqlite、time 等参考实现。
- **社区**：数千个 Server，覆盖数据库、浏览器、邮件、支付、监控。
- **排查套路**（三层法，和排查接口一致）：
  1. Server 是否启动、进程是否存活（看日志）。
  2. 传输是否通（stdio 看启动参数、远程看 URL/鉴权）。
  3. 能力与权限（initialize 是否成功、工具是否在列表、Host 是否放行）。

## 测开视角

- **AI 测试平台的基础设施**：AI 要"发请求、跑用例、查日志、读数据库"，都通过 MCP 接，不再为每个 AI 定制。
- **让 AI 干活的具体姿势**：
  - 接数据库 MCP：AI 读测试数据、造数、验数。
  - 接日志 MCP：AI 排查失败用例的报错堆栈。
  - 接接口/压测 MCP：AI 触发回归、看报告。
- **企业落地步骤**：盘点工具 → 按最小权限包 Server → 配 Host 白名单 → 加审计 → 灰度开放。
- **测试重点**：Server 的鉴权、超时、并发、参数校验、脱敏——MCP Server 是一个新的被测对象。

## 面试高频题

- **Q**：MCP 的三类核心能力是什么？**A**：Tool（可调用动作）、Resource（只读数据）、Prompt（模板），分别对应执行、读取、引导。
- **Q**：MCP 安全上怎么防模型乱调工具？**A**：用户/宿主授权、Tool 白名单、roots 限范围、危险操作弹确认、审计日志。
- **Q**：stdio 和远程传输怎么选？**A**：本地进程用 stdio（简单安全）；跨机器/多客户端用 Streamable HTTP（需鉴权、可扩展）。
- **Q**：MCP Server 上线前要测什么？**A**：鉴权、超时、并发、参数校验、脱敏、审计——当接口测。
