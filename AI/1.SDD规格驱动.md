## SDD 是什么

- **SDD**（Specification-Driven Development，规格驱动开发）：**规格（Specification）是开发的唯一权威输入**，代码、测试、文档都从规格派生。
- **规格不是需求文档**：需求文档描述"想要什么"，规格描述"系统在每种输入下必须产生什么输出"——是可判定对错的契约。
- **核心主张**：先消除歧义，再写代码；歧义在规格层解决的成本，远低于在编码/测试层解决。
- **本质**：把"需求 → 代码"的跳跃，拆成"需求 → 规格（可验证）→ 代码（可对照）"两步。

## 规格的分层

- **业务规格**：用户故事 + 验收标准（AC），回答"业务上要达成什么"。
- **场景规格**：Given-When-Then 场景集，回答"每种情况下系统怎么表现"。
- **接口规格**：字段级契约（入参/出参/类型/约束/错误码），回答"系统边界上收什么发什么"。
- **数据规格**：字段字典、枚举值、关联规则，回答"数据长什么样"。
- **分层目的**：上层面向人（业务评审），下层面向机器（直接生成测试和代码）。

### 接口规格示例（字段级）

```
接口：POST /api/login
入参：
  username   string  必填  3~32 位，字母数字下划线
  password   string  必填  6~20 位，含字母和数字
出参：
  code       int    业务码，0=成功
  data.token string  成功时返回 JWT
错误码：
  1001  密码错误
  1002  账号不存在
  1003  参数不合法
```

#### 规格如何落地

- 这份规格可以**直接翻译成测试用例**：username 边界（2/3/32/33 位）、password 组合、缺字段、错误码分支。
- 也可以**直接翻译成 mock 和契约测试**：前端按它 mock，后端按它实现，两端不打架。

## 与 TDD / BDD / DDD 的关系

- **TDD**：测试先行，关注"怎么写才正确"（微观，方法级）。
- **BDD**：行为驱动，用 Given-When-Then 让业务参与，关注"怎么描述需求"（表达层）。
- **DDD**：领域驱动，关注"领域模型怎么设计"（架构层）。
- **SDD**：规格先行，关注"先定行为契约再实现"（流程层）。
- **关系**：SDD 是流程框架，可内嵌 BDD 的 Given-When-Then 做规格表达，用 TDD 做实现层验证，用 DDD 定边界——不冲突，互补。

## 工作流程

1. **写规格**：按分层产出业务/场景/接口/数据规格，格式可读且可机器解析。
2. **评审规格**：业务、开发、测试三方评审；用场景穷举法找歧义（"如果…怎么办"逐个问）。
3. **规格入库**：规格本身进版本库，随代码一起 review、一起发版。
4. **派生产物**：从规格生成测试用例、mock、接口文档、代码骨架。
5. **验证闭环**：实现完成后，规格驱动的测试逐条对照，任何一条不通过 = 规格或实现有问题。
6. **变更管理**：需求变化先改规格 → 评估影响范围 → 改代码 + 回归对应用例。

## AI 时代的 SDD（关键）

- **规格 = 给 AI 的提示词**：AI 生成代码/用例/文档的质量，上限取决于规格质量。规格写得越无歧义，AI 产出越准。
- **人机协作模式**：
  - 人写规格（业务理解不可替代）→ AI 按规格生成实现 + 测试 + 文档。
  - AI 辅助查规格漏洞（反向提问："规格没覆盖空值场景，是否补充？"）。
- **AI 生成内容的验收**：没有规格，AI 产出无法验证；有规格，验证 = 逐条对照。
- **测开的新岗位价值**：会写高质量规格（含边界、异常、性能约束）的人，决定 AI 产出的质量——规格工程师。

## 测开落地要点

- **Spec-to-Case 管线**：接口规格 → 自动展开等价类/边界/错误码用例，减少手写。
- **规格覆盖率**：像代码覆盖率一样度量"哪些规格点没有对应用例"。
- **契约测试**：接口规格即契约，消费方和提供方各跑契约测试，防两端漂移。
- **可测试性前置**：规格阶段就暴露"这需求没法测"（无明确输出、依赖时序），倒逼需求澄清。

## 面试高频题

- **Q**：SDD 和 TDD 的本质区别？**A**：TDD 用测试表达"怎么做"，SDD 用规格表达"做什么"；SDD 更早介入需求层，测试是规格的验证落地。
- **Q**：AI 时代 SDD 为什么更重要？**A**：规格是 AI 生成的唯一权威输入，规格质量决定 AI 产出质量，人机协作的锚点在规格。
- **Q**：怎么让规格可验证？**A**：场景化（Given-When-Then）+ 字段级契约（类型/边界/错误码），每条都可翻译成可判定用例。
- **Q**：规格和需求文档有什么区别？**A**：需求是意图，规格是行为契约；规格可机器解析、可派生测试、可判对错。
