## Skills 是什么

- **Skill（技能）**：一个目录 + 一个 `SKILL.md` 文件，**教 AI 智能体"怎么做一件具体的事"**——把团队流程、专业知识、工作偏好打包成可复用文件，智能体按需加载。
- **一句话**：给 AI 的"岗位说明书"——平时不占空间，用到时自动加载完整操作手册。
- **两种调用方式**：模型自动调用（按描述匹配触发）vs 用户手动调用（`/技能名` 斜杠命令）。

## 为什么需要

- **流程知识没处放**：团队的发布检查、代码评审、bug 报告格式——之前放人脑（每次重新打）、放巨型指令文件（全量加载浪费上下文）、放工具专属配置（换工具就重写）。
- **系统提示词膨胀**：所有约定塞进系统提示词，每请求都加载，上下文被无关内容挤占。
- **Skill 的解法**：**渐进式披露**——启动只花 ~100 tokens 看技能名和描述，用到时才加载完整内容。装 50 个技能，上下文成本只等于 1 个常驻文件。
- **典型应用**：把团队测试流程做成 Skill——用例设计规范、接口压测流程、bug 报告模板、回归验证清单，任何智能体都按统一标准干活；流程经验沉淀为可复用技能，是团队知识工程的一部分。

## 目录结构与文件

- **SKILL.md 是开放标准格式**（规范见 agentskills.io）：主流编码智能体（Claude Code、Cursor、Codex、Gemini CLI、VS Code、Copilot 等 40+ 工具）都原生支持——一个技能目录写一次，处处可用。

### 目录树

```
skill-name/                  # 目录名 = 技能名（小写连字符）
├── SKILL.md                 # 必需：frontmatter + Markdown 指令
├── scripts/                 # 可选：可执行脚本（Python/Bash/JS）
├── references/              # 可选：按需加载的详细文档
├── examples/                # 可选：示例输出
└── assets/ / templates/     # 可选：模板、数据文件
```

#### 关键字段

- **SKILL.md 只需要两个关键字段**：`name`（技能名，与目录名一致）和 `description`（做什么 + 什么时候用——智能体触发技能的唯一依据，最重要的字段）。其余字段（工具白名单、模型选择等）都是可选配置，用的时候再查。

## 编排一个 Skill 的多样性

- 同一个 SKILL.md 标准，能编排出**多种形态的技能**——按"这个任务要什么"来选形态，没有固定的唯一写法。

### 纯知识型（参考类）

- **形态**：只有 SKILL.md，正文就是约定/规范本身，无脚本无模板。
- **用途**：给智能体注入团队规范、领域知识，工作时不照搬但必须遵守。
#### 示例（代码库 API 约定）

```
---
name: api-conventions
description: 本代码库的 API 设计约定。写接口或评审接口时使用。
---

编写 API 端点时：
- 使用 RESTful 命名约定
- 返回一致错误格式 { code, message, details }
- 所有端点必须有 OpenAPI 注释
```

### 脚本任务型（单脚本）

- **形态**：SKILL.md 引导 + `scripts/` 一个脚本，智能体按步骤调用脚本完成固定任务。
- **用途**：流程确定、结果确定的任务（文件转换、格式化、数据清洗）。
- **要点**：脚本代码不进上下文，智能体只看到输出——脚本写得越可靠，技能越稳。

### 流水线型（多脚本协作）

- **形态**：`scripts/` 下多个脚本，SKILL.md 描述**执行顺序**（先 A 再 B 再 C），像一条流水线。
- **用途**：多步骤任务（采集 → 清洗 → 校验 → 出报告）。
- **示例**（数据报告）：
  1. `scripts/fetch.py` 拉数据
  2. `scripts/clean.py` 清洗
  3. `scripts/report.py` 生成报告
- **要点**：SKILL.md 里写清每步的输入输出和依赖，智能体按序执行、任一步失败即停。

### 模板产出型

- **形态**：SKILL.md + `templates/`（或 assets/）模板文件，智能体套模板产出固定格式内容。
- **用途**：周报、bug 报告、发布说明、PR 描述这类"格式必须统一"的产出。
- **示例**（周报）：SKILL.md 描述要点结构 → 智能体按 `templates/weekly-report.md` 填内容。

### 子 agent 执行型（隔离上下文）

- **形态**：SKILL.md 里配置在**独立子 agent 上下文**运行（`context: fork` + 指定 agent 类型）。
- **用途**：任务重、不想污染主对话、或需要专门 agent 能力（如用 Explore 只读排查）。
- **示例**（代码审查）：`context: fork` + `agent: Explore`——审查在独立上下文进行，结果返回主对话。

### 组合协同型（多 Skill 协作）

- **形态**：一个 Skill 的指令里明确"先调用哪个 Skill、再调用哪个"——技能之间接力。
- **用途**：复杂工作流拆成多个小技能复用。
- **示例**：`release` 技能里写"先运行 `data-prep` 技能准备数据，再运行 `report-gen` 技能生成发布说明"。
- **要点**：拆分的粒度 = 可复用边界；公共能力（发请求、读库）做成基础技能，业务技能引用它们。

### 与 Agent 的组合

- **Agent 挂载 Skill**：自定义 agent 定义里声明 `skills: skill1, skill2`，该 agent 启动时把技能内容注入自己的上下文。
- **Skill 指定 Agent**：技能用 `context: fork` + `agent: <类型>` 委托给某个子 agent 执行。
- **多 agent 协作**：主 agent 用 Task 工具派发多个子 agent，每个子 agent 挂各自的 skills——技能管"怎么做"，agent 管"谁来做"。

## 动态参数（让技能可复用）

- **$ARGUMENTS**：调用时传入的全部参数（如 `/fix-issue 234` → `$ARGUMENTS` = 234）。
- **$ARGUMENTS[N] / $N**：第 N 个参数。
- **$name**：frontmatter `arguments` 里声明的命名参数。
- **${CLAUDE_SKILL_DIR}**：技能目录路径（引用同目录文件时用）。
- **用途**：同一个技能用参数适配不同输入，不用为每个输入写一个新技能。

## 渐进式披露（核心机制）

- **三阶段加载**：
  1. 启动时：只看每个技能的 name + description（约 100 tokens/个）。
  2. 任务匹配时：加载完整 SKILL.md 正文（规范建议 <5000 tokens / <500 行）。
  3. 执行中：按需读 references 文档或运行 scripts 脚本（脚本代码不进上下文，只看输出）。
- **为什么关键**：上下文才是瓶颈，不是模型能力。Skill 让"成本为 0 直到相关的那一刻"。

## 写好一个 Skill 的要点

- **description 最重要**：第三人称，写"做什么 + 何时用 + 触发词"（像函数签名）。写模糊了（"帮助处理 PDF"）永远不会被触发，且不报错。
- **命名规范**：用 gerund 形式（processing-pdfs、testing-code）；避免 helper/utils 这类模糊名。
- **正文精简**：主文件 <500 行，细节放 references/。
- **正文分步清晰**：步骤 + 输入输出示例 + 边界情况。
- **形态选对**：纯约定用知识型、固定任务用脚本型、格式产出用模板型、重任务用子 agent 型——按任务选形态。

## Skills 与 MCP / AGENTS.md 的关系

- **MCP**：给智能体"手"——连接工具和数据（怎么调用外部能力）。
- **Skills**：教智能体"方法"——怎么做事（流程、规范、领域知识）。
- **两者互补**：MCP 解决"能不能调"，Skills 解决"该怎么做"。
- **AGENTS.md / CLAUDE.md**：项目级常驻上下文，全量加载；Skills 按需加载——粒度不同，Skill 更省上下文。

## 放置层级与优先级

- **Enterprise（企业级）**：组织统一管理，最高优先级。
- **Personal（个人）**：`~/.claude/skills/`，所有项目可用。
- **Project（项目级）**：`.claude/skills/`，进 git 团队共享。
- **Plugin（插件）**：随插件安装自带。
- **同名冲突**：高优先级覆盖低优先级（企业 > 个人 > 项目 > 插件）。

## 生态与安全

- **获取方式**：官方 showcase、社区注册表（skills.sh 等）、`npx skills add owner/repo` 一键安装。
- **安全风险（必须知道）**：审计发现相当比例的公开技能存在安全问题——**装技能先审查**（看 SKILL.md 和 scripts，别执行来历不明的脚本），和装第三方依赖一个心态。

## 面试高频题

- **Q**：Agent Skills 是什么？**A**：一个目录 + SKILL.md，教 AI 智能体怎么做具体任务，按需加载的可复用指令包。
- **Q**：渐进式披露是什么？**A**：启动只加载技能名和描述，任务匹配才加载完整正文，细节按需读——控制上下文成本。
- **Q**：SKILL.md 里 description 为什么最重要？**A**：它是模型决定是否加载技能的唯一依据，写清"做什么+触发词"，写模糊就永远不会被触发。
- **Q**：Skill 有哪些编排形态？**A**：纯知识型（注入约定）、脚本任务型（单脚本）、流水线型（多脚本按序）、模板产出型、子 agent 执行型（隔离上下文）、组合协同型（多技能接力）、与 agent 挂载组合。
- **Q**：Skill 和 Agent 怎么协作？**A**：Skill 可指定 context: fork + agent 在子 agent 上下文运行；agent 也可在定义里挂载 skills，启动时注入上下文；主 agent 用 Task 派发多 agent 协作。
- **Q**：Skills 和 MCP 的区别？**A**：MCP 连接工具和数据（给手），Skills 教方法和流程（教怎么做），两者互补。
