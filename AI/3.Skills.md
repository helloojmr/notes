## Skills 是什么

- **Skill（技能）**：一个目录 + 一个 `SKILL.md` 文件，**教 AI 智能体"怎么做一件具体的事"**——把团队流程、专业知识、工作偏好打包成可复用文件，智能体按需加载。
- **一句话**：给 AI 的"岗位说明书"——平时不占空间，用到时自动加载完整操作手册。
- **类比**：AI 编码助手是新的 IDE，Skills 就是它的"扩展市场"，而且一个扩展处处通用。

## 为什么需要

- **流程知识没处放**：团队的发布检查、代码评审、bug 报告格式、压测流程——之前放人脑（每次重新打）、放巨型指令文件（每次全量加载浪费上下文）、放工具专属配置（换工具就得重写）。
- **系统提示词膨胀**：把所有约定塞进系统提示词，每请求都加载，上下文被无关内容挤占。
- **Skill 的解法**：**渐进式披露**——启动只花 ~100 tokens 看技能名和描述，用到时才加载完整内容。装 50 个技能，上下文成本只等于 1 个常驻文件。

## 目录结构与文件

- **SKILL.md 是开放标准格式**（规范见 agentskills.io）：主流编码智能体（Claude Code、Cursor、Codex、Gemini CLI、VS Code、Copilot 等 40+ 工具）都原生支持——一个技能目录写一次，处处可用。

#### 目录树

```
skill-name/                  # 目录名 = 技能名（小写连字符）
├── SKILL.md                 # 必需：YAML frontmatter + Markdown 指令
├── scripts/                 # 可选：可执行脚本（Python/Bash/JS）
├── references/              # 可选：按需加载的详细文档
└── assets/                  # 可选：模板、数据文件
```

### SKILL.md 的 frontmatter（元数据）

- **name**（必需）：≤64 字符，小写字母/数字/连字符，**必须与目录名一致**。
- **description**（必需）：≤1024 字符，讲清楚"做什么 + 什么时候用"——**这是智能体决定要不要加载技能的唯一依据**。
- **license**（可选）：SPDX 标识（如 MIT）。
- **compatibility**（可选）：环境要求（"需要 git 和 docker"）。
- **metadata**（可选）：任意键值（作者、版本、标签）。
- **allowed-tools**（可选，实验性）：预授权的工具白名单。

#### 完整示例

```
---
name: release-checklist
description: 执行发布前验证清单。在打 tag 发布前，或用户说"准备发布"时使用。
license: MIT
metadata:
  version: 1.0.0
---

# 发布前检查

1. 运行 `git log $(git describe --tags --abbrev=0)..HEAD --oneline` 确认变更。
2. 按 conventional commits 类型（feat/fix/chore）分组提交。
3. 对照 references/CHECKLIST.md 逐项验收。
4. 通过后打 tag 并推送。
```

## 渐进式披露（核心机制）

- **三阶段加载**：
  1. 启动时：只看每个技能的 name + description（约 100 tokens/个）。
  2. 任务匹配时：加载完整 SKILL.md 正文（规范建议 <5000 tokens / <500 行）。
  3. 执行中：按需读 references 文档或运行 scripts 脚本（脚本代码不进上下文，只看输出）。
- **为什么关键**：上下文才是瓶颈，不是模型能力。Skill 让"成本为 0 直到相关的那一刻"。
- **反面**：所有约定堆进 AGENTS.md / CLAUDE.md，每请求全量加载，就是渐进式披露要解决的问题。

## 写好一个 Skill 的要点

- **description 最重要**：写得像函数签名——"做什么 + 用户会说的触发词"。写模糊了（"帮助处理 PDF"）智能体永远不会加载，而且不会报错，只会即兴发挥。
- **正文分步清晰**：步骤 + 输入输出示例 + 边界情况。
- **正文保持精简**：细节放 references/，主文件 <500 行。
- **放对位置**：Claude Code 中 `~/.claude/skills/`（个人全局）、`.claude/skills/`（项目内）；其他工具类似约定。

## Skills 与 MCP / AGENTS.md 的关系

- **MCP**：给智能体"手"——连接工具和数据（怎么调用外部能力）。
- **Skills**：教智能体"方法"——怎么做事（流程、规范、领域知识）。
- **两者互补**：MCP 解决"能不能调"，Skills 解决"该怎么做"。一个 MCP Server 给手，一个 Skill 教怎么用这双手干活。
- **AGENTS.md / CLAUDE.md**：项目级常驻上下文，全量加载；Skills 按需加载——粒度不同，Skill 更省上下文。

## 生态与安全

- **获取方式**：官方 showcase、社区注册表（skills.sh 等）、`npx skills add owner/repo` 一键安装。
- **安全风险（必须知道）**：Snyk ToxicSkills 审计发现扫描的技能中 13.4% 存在严重问题——**装技能先审查**（看 SKILL.md 和 scripts，别执行来历不明的脚本），和装第三方依赖一个心态。

## 测开视角

- **把测试流程做成 Skill**：用例设计规范、接口压测流程、bug 报告模板、回归验证清单——写成 Skill 后团队任何智能体都能按统一标准干活。
- **AI 测试工具的"标准操作手册"**：比如"用 JMeter 压测并产出报告"做成 Skill，AI 执行压测时自动按规范来。
- **技能即资产**：测开的流程经验沉淀为可复用 Skill，是团队知识工程的一部分。
- **自己动手**：写一个"提交信息规范"或"接口用例生成"Skill，练手成本就是一个文件夹 + 一个 md 文件。

## 面试高频题

- **Q**：Agent Skills 是什么？**A**：一个目录 + SKILL.md，教 AI 智能体怎么做具体任务，按需加载的可复用指令包。
- **Q**：渐进式披露是什么？**A**：启动只加载技能名和描述，任务匹配才加载完整正文，细节按需读——控制上下文成本。
- **Q**：SKILL.md 里 description 为什么最重要？**A**：它是智能体决定是否加载技能的唯一依据，写清"做什么+触发词"，写模糊就永远不会被触发。
- **Q**：Skills 和 MCP 的区别？**A**：MCP 连接工具和数据（给手），Skills 教方法和流程（教怎么做），两者互补。
- **Q**：装社区 Skill 要注意什么？**A**：先审查 SKILL.md 和 scripts，有 13%+ 的公开技能存在安全问题，别执行来历不明的脚本。
