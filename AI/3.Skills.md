## Skills 是什么

- **Skill（技能）**：一个目录 + 一个 `SKILL.md` 文件，**教 AI 智能体"怎么做一件具体的事"**——把团队流程、专业知识、工作偏好打包成可复用文件，智能体按需加载。
- **一句话**：给 AI 的"岗位说明书"——平时不占空间，用到时自动加载完整操作手册。
- **两种调用方式**：模型自动调用（按 description 匹配触发）vs 用户手动调用（`/技能名` 斜杠命令）。

## 为什么需要

- **流程知识没处放**：团队的发布检查、代码评审、bug 报告格式——之前放人脑（每次重新打）、放巨型指令文件（全量加载浪费上下文）、放工具专属配置（换工具就重写）。
- **系统提示词膨胀**：所有约定塞进系统提示词，每请求都加载，上下文被无关内容挤占。
- **Skill 的解法**：**渐进式披露**——启动只花 ~100 tokens 看技能名和描述，用到时才加载完整内容。
- **典型应用**：把团队测试流程做成 Skill——用例设计规范、接口压测流程、bug 报告模板、回归验证清单，任何智能体都按统一标准干活；流程经验沉淀为可复用技能，是团队知识工程的一部分。

## 目录结构与文件

- **SKILL.md 是开放标准格式**（规范见 agentskills.io）：主流编码智能体（Claude Code、Cursor、Codex、Gemini CLI、VS Code、Copilot 等 40+ 工具）都原生支持——一个技能目录写一次，处处可用。

### 目录树

```
skill-name/                  # 目录名 = 技能名（小写连字符）
├── SKILL.md                 # 必需：YAML frontmatter + Markdown 指令
├── scripts/                 # 可选：可执行脚本（Python/Bash/JS）
├── references/              # 可选：按需加载的详细文档
├── examples/                # 可选：示例输出
└── assets/                  # 可选：模板、数据文件
```

#### 辅助文件引用

- 从 SKILL.md 里引用辅助文件（如 `见 [reference.md](reference.md)`），智能体用到时才加载。

## SKILL.md 的配置（YAML frontmatter）

- 文件顶部 `---` 之间的 YAML 块就是配置，下面全是 Markdown 指令正文。

### 基础字段

- **name**：≤64 字符，小写字母/数字/连字符，必须与目录名一致；省略时用目录名。
- **description**：≤1024 字符，写"做什么 + 什么时候用"——**模型决定是否加载技能的唯一依据**，最重要的字段。
- **when_to_use**：补充触发词/示例请求，与 description 合计 ≤1536 字符。
- **license**：SPDX 标识（如 MIT）。
- **compatibility**：环境要求（"需要 git 和 docker"）。
- **metadata**：任意键值（作者、版本、标签）。

### 控制字段（Claude Code 扩展）

- **allowed-tools**：技能激活时**预授权**的工具白名单（如 `Read, Grep, Glob`）——列出的工具免权限弹窗，同时**限定只能用它列出的工具**，不写则继承默认权限模型。
- **disable-model-invocation**：`true` = 只允许用户手动调用（`/技能名`），模型不自动触发——适合有副作用的流程（部署）。
- **user-invocable**：`false` = 从 `/` 菜单隐藏，只让模型自动调用——适合后台知识类技能。
- **model**：技能激活时切换的模型。
- **effort**：覆盖努力等级（low / medium / high / xhigh / max）。
- **context: fork**：在**独立子 agent 上下文**里运行（隔离上下文，不污染主对话）。
- **agent**：`context: fork` 时指定用哪个 subagent 执行（Explore / Plan / general-purpose / 自定义 agent）。
- **hooks**：技能生命周期钩子（如 PostSkillUse 执行命令）。
- **paths**：glob 模式限定自动激活的文件范围（如 `src/**/*.ts`）。

### 完整示例

```
---
name: release-checklist
description: 执行发布前验证清单。在打 tag 发布前，或用户说"准备发布"时使用。
when_to_use: 发布、发版、ship
allowed-tools: Read, Grep, Glob, Bash(git *)
context: fork
agent: general-purpose
metadata:
  version: 1.0.0
---

# 发布前检查

1. 运行 `git log $(git describe --tags --abbrev=0)..HEAD --oneline` 确认变更。
2. 按 conventional commits 类型（feat/fix/chore）分组提交。
3. 对照 references/CHECKLIST.md 逐项验收。
4. 通过后打 tag 并推送。
```

## 动态参数（字符串替换）

- **$ARGUMENTS**：调用时传入的全部参数。
- **$ARGUMENTS[N]**：第 N 个参数（0 开始），简写 **$N**。
- **$name**：frontmatter `arguments` 里声明的命名参数（如 `arguments: [issue, branch]` → `$issue`、`$branch`）。
- **${CLAUDE_SKILL_DIR}**：技能目录路径（引用同目录文件时用）。
- **argument-hint**：自动补全时的参数提示（如 `[issue-number]`）。

## 内容类型：参考 vs 任务

- **参考类（Reference）**：把知识注入上下文，智能体工作时应用——如"本仓库的 API 设计约定"（api-conventions）。
- **任务类（Task）**：给智能体执行的分步指令——如"部署到生产"（deploy），通常配 `context: fork` + `disable-model-invocation`。
- **选择标准**：要不要执行动作？纯约定 → 参考类；要执行流程 → 任务类。

## Skill 与 Agent 的协作

- **Skill 不是"调用多个 agent"的容器**——它是"做什么"的指令包；但它可以和 agent 双向配合：
- **Skill 指定 agent 执行**：`context: fork` + `agent: <类型>`——技能在指定 subagent 的隔离上下文里运行（独立上下文、可选不同模型）。
- **Agent 挂载 Skill**：自定义 agent（`.claude/agents/agent-name.md`）frontmatter 里声明 `skills: skill1, skill2`——该 agent 启动时把技能内容注入自己的上下文。
- **多 agent 协作模式**：主 agent 用 Task 工具派发子任务给多个 subagent，每个 subagent 挂各自的 skills——技能负责"怎么做"，agent 负责"谁来做"。

## 放置层级与优先级

- **Enterprise（企业级）**：组织统一管理，最高优先级。
- **Personal（个人）**：`~/.claude/skills/`，所有项目可用。
- **Project（项目级）**：`.claude/skills/`，进 git 团队共享。
- **Plugin（插件）**：随插件安装自带。
- **同名冲突**：高优先级覆盖低优先级（企业 > 个人 > 项目 > 插件）。
- **生效方式**：增删改技能文件**实时生效**（无需重启）；新建不存在的顶层 skills 目录才需要重启。

## 渐进式披露（核心机制）

- **三阶段加载**：
  1. 启动时：只看每个技能的 name + description（约 100 tokens/个）。
  2. 任务匹配时：加载完整 SKILL.md 正文（规范建议 <5000 tokens / <500 行）。
  3. 执行中：按需读 references 文档或运行 scripts 脚本（脚本代码不进上下文，只看输出）。
- **为什么关键**：上下文才是瓶颈，不是模型能力。Skill 让"成本为 0 直到相关的那一刻"。

## 写好一个 Skill 的要点

- **description 最重要**：第三人称，写"做什么 + 何时用 + 触发词"（像函数签名）。写模糊了（"帮助处理 PDF"）永远不会被触发，且不报错。
- **命名规范**：用 gerund 形式（processing-pdfs、testing-code）；避免 helper/utils 这类模糊名；保留字（anthropic-helper 等）不能用。
- **正文精简**：主文件 <500 行，细节放 references/。
- **正文分步清晰**：步骤 + 输入输出示例 + 边界情况。

## Skills 与 MCP / AGENTS.md 的关系

- **MCP**：给智能体"手"——连接工具和数据（怎么调用外部能力）。
- **Skills**：教智能体"方法"——怎么做事（流程、规范、领域知识）。
- **两者互补**：MCP 解决"能不能调"，Skills 解决"该怎么做"。
- **AGENTS.md / CLAUDE.md**：项目级常驻上下文，全量加载；Skills 按需加载——粒度不同，Skill 更省上下文。

## 生态与安全

- **获取方式**：官方 showcase、社区注册表（skills.sh 等）、`npx skills add owner/repo` 一键安装。
- **安全风险（必须知道）**：审计发现相当比例的公开技能存在安全问题——**装技能先审查**（看 SKILL.md 和 scripts，别执行来历不明的脚本），和装第三方依赖一个心态。
- **allowed-tools 是安全手段**：把技能限定到最小工具集，降低被滥用的面。

## 面试高频题

- **Q**：Agent Skills 是什么？**A**：一个目录 + SKILL.md，教 AI 智能体怎么做具体任务，按需加载的可复用指令包。
- **Q**：渐进式披露是什么？**A**：启动只加载技能名和描述，任务匹配才加载完整正文，细节按需读——控制上下文成本。
- **Q**：SKILL.md 里 description 为什么最重要？**A**：它是模型决定是否加载技能的唯一依据，写清"做什么+触发词"，写模糊就永远不会被触发。
- **Q**：allowed-tools 的作用？**A**：技能激活时预授权工具白名单（免权限弹窗），同时限定只能用它列出的工具——能力收敛、更安全。
- **Q**：Skill 和 Agent 怎么协作？**A**：Skill 可指定 context: fork + agent 在子 agent 上下文运行；agent 也可在定义里挂载 skills，启动时注入上下文；主 agent 用 Task 派发多 agent 协作。
- **Q**：Skills 和 MCP 的区别？**A**：MCP 连接工具和数据（给手），Skills 教方法和流程（教怎么做），两者互补。
