## 参数化是什么

- **为什么需要**：脚本里的数据不能写死——同一账号反复登录会被服务端限流/踢下线，业务数据要求唯一性，真实场景是成百上千个用户。
- **定义**：用变量替换脚本中的硬编码值，运行时从数据源取不同数据填进去。
- **核心语法**：`${变量名}` 引用变量，JMeter 运行时自动替换。
- **对应代码**：Python 里遍历列表取账号、`random` 造随机数、从数据库读数据，本质都是"数据不写死在代码里"。
- **测开**：参数化 = 测试数据的生成与分发，是接口/性能测试数据准备的 JMeter 落地形态。

## 变量引用与作用域

- **引用语法**：`${username}`，出现在路径、参数、Body Data、Header 里都会自动替换。
- **变量来源**
  - CSV 参数化：每行数据一个变量的值
  - 用户自定义变量/用户参数：手动定义
  - 函数：动态生成
  - 后置处理器提取(关联)：从响应中提取
- **作用域**
  - 普通变量：当前线程组内有效(跨线程组拿不到)
  - 全局属性：`${__setProperty(名,值,)}` 写入 + `${__P(名)}` 读取，跨线程组传参用
- **面试话术**：变量取不到值，先看变量定义在哪、引用在哪，作用域是否覆盖；跨线程组必须走 `__setProperty` + `__P`。

## CSV Data Set Config(最常用)

- **位置**：右键线程组 → 添加 → 配置元件 → CSV 数据文件设置。
- **作用**：从 CSV 文件按行读取数据，赋值给变量，每行数据供一次请求使用。
- **核心配置项**
  - **文件名**：CSV 路径，放 JMeter bin 目录可直接写文件名
  - **文件编码**：选 `UTF-8`，否则中文乱码
  - **变量名称**：逗号分隔，与 CSV 列一一对应，如 `username,password`
  - **分隔符**：默认 `,`（逗号）
  - **遇到文件末尾(Recycle on EOF)**：True 读完循环从头读；False 读完不再有数据
  - **停止线程(Stop thread on EOF)**：True 时文件读完线程直接停止(需配合 Recycle 关闭)
  - **线程共享模式(Sharing mode)**
    - **所有线程(All threads)**：所有线程共用一个数据游标，一行只被取一次——并发取不同账号，最常用
    - **当前线程组(Current thread group)**：仅本线程组内共享
    - **当前线程(Current thread)**：每个线程各自从头读，数据会重复
- **示例**：`users.csv` 两列 500 行账号 → 变量名 `username,password` → 请求里 `${username}`、`${password}`。
- **测开**：Sharing mode 选"所有线程"保证并发不重号；账号数要 ≥ 并发数，否则会循环复用。

## 其他参数化方式

### 用户自定义变量(User Defined Variables)

- 位置：右键测试计划/线程组 → 添加 → 配置元件 → 用户定义的变量。
- 特点：**全局静态常量**，所有线程共用一个值，运行中不变。
- 适用：`base_url`、公共请求头、环境标识等固定配置。
- 对比 CSV：一个变量一个固定值，不能做到每线程不同。

### 用户参数(User Parameters)

- 位置：右键线程组 → 添加 → 预处理器 → 用户参数。
- 特点：手动维护若干行数据，行列组合若干用户的若干参数，配合循环次数每次迭代取一列。
- 适用：少量用户(10 个以内)、数据量小不想建文件的场景。
- 注意：数据写死在脚本里，量大时不方便维护，适合演示/小规模。

### 函数参数化

- **`${__Random(1,100)}`**：随机数，如随机用户 ID、随机金额。
- **`${__counter(TRUE,)}`**：计数器，TRUE 每个线程独立计数，FALSE 全局计数，用于生成序号。
- **`${__time(yyyy-MM-dd HH:mm:ss,)}`**：当前时间格式化，如订单时间、时间戳。
- **`${__UUID()}`**：生成唯一 ID，业务主键唯一性场景。
- **组合用法**：订单号 = `${__time(yyyyMMddHHmmss)}${__counter(FALSE,)}`，保证并发不重复。
- 对应代码：`random.randint()`、`time.strftime()`、`uuid.uuid4()`。

### JDBC 参数化 📖 补充

- 场景：数据量巨大或需要真实业务数据(如真实用户表)，从数据库直接取。
- 配置：JDBC Connection Configuration(数据库连接) + JDBC Request(执行 SQL) → 结果存变量 → 请求引用。
- 适用：数据上百万、CSV 文件撑不住，或要求数据必须真实存在。
- **测开**：这是 25k+ 岗位常问的进阶点——测试数据不落地造，直接"读生产/测试库的真实数据"。

## 数据准备策略(测开视角)

- **账号类**：脚本批量造数(调注册接口/直插数据库)，CSV 落盘，几千个起步。
- **随机类**：函数现场生成，不落盘，如随机金额、随机 ID。
- **边界类**：参数化要包含边界数据——空值、超长、特殊字符，呼应测试理论边界值分析。
- **真实数据**：JDBC 直读业务库，保证数据可信。
- **面试话术**：参数化不只是"文件循环读"，背后是测试数据管理——数据从哪来、够不够、会不会重复、要不要脱敏。

## 实战案例

### 案例一：CSV 多账号并发登录

- 场景：500 个账号并发压测登录，每个线程用不同账号。
- 配置步骤：
  - 准备 `users.csv`(500 行 `username,password`) → CSV Data Set Config：变量名 `username,password`、Sharing mode 选"所有线程"、编码 UTF-8
  - 线程组 100 并发，HTTP 请求 POST `/api/login`，Body Data `{"username":"${username}","password":"${password}"}`
  - 运行后用聚合报告 + 查看结果树确认账号确实在变化
- 验证技巧：断言里加一个请求参数带 `${username}`，结果树里能看到每次请求的账号不同。

### 案例二：订单号唯一性(函数组合)

- 场景：并发创建订单，订单号必须唯一，否则数据库主键冲突报错。
- 配置：订单号用 `${__time(yyyyMMddHHmmss)}${__counter(FALSE,)}` 组合生成，Body Data 里 `${orderNo}` 引用。
- 验证：压测后查订单表订单号无重复。
- **测开**：并发下主键/唯一索引冲突是经典性能问题，参数化唯一性是第一道防线。

### 案例三：多用户混跑(用户参数)

- 场景：3 个角色用户(普通/会员/管理员)混跑业务。
- 配置：用户参数里定义 3 行 `role,userId`，线程组循环次数设为 3 的倍数，每次迭代取一行。
- 适用判断：角色少、数据少用用户参数；数据多一律 CSV。

## 面试高频题

- **Q**：JMeter 参数化有哪几种方式？**A**：CSV Data Set Config(最常用)、用户自定义变量、用户参数、函数(__Random/__counter/__time)、JDBC；按数据量大小和来源选择。
- **Q**：CSV 文件读完了怎么办？**A**：勾选 Recycle on EOF 循环复用；或关闭循环并勾选 Stop thread on EOF 让线程停止。
- **Q**：怎么保证并发用户取不同账号？**A**：CSV 线程共享模式选"所有线程(All threads)"，数据游标全局共享，一行只取一次；账号数 ≥ 并发数。
- **Q**：CSV 中文乱码怎么办？**A**：文件编码选 UTF-8，且 CSV 文件本身要以 UTF-8 保存。
- **Q**：跨线程组传参怎么做？**A**：普通变量只在组内有效，用 `${__setProperty}` 写成全局属性，目标线程组 `${__P()}` 读取。
- **Q**：测试数据怎么准备？**A**：账号类脚本造数落 CSV；随机类函数现场生成；海量/真实数据用 JDBC 直读业务库；注意边界数据覆盖与脱敏。
