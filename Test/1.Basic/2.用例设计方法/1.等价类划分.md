- **性能**
  - 花瓶测试点：防摔、耐压
  - **实战要点**：压力测试（高并发）、稳定性测试（长时间运行）

- **可靠性**
  - 花瓶测试点：长时间盛水不渗漏
  - **实战要点**：长期稳定性测试（7x24小时运行）、故障注入
- **安全性**
  - 花瓶测试点：材质环保、无锐边
  - **实战要点**：安全扫描（SQL注入、XSS）、权限测试

## 等价类划分法

### 1. 定义

- 把所有可能的输入数据划分成若干个子集（等价类），从每个子集中选取少量代表性数据进行测试。其核心思想是：如果某个等价类中的一个值能发现缺陷，那么该等价类中的其他值也能发现类似缺陷。
- 等价类划分不仅用于输入，还可用于**输出、状态、配置**等。在自动化测试中，等价类思想可用于**数据驱动**：将测试数据分类，用参数化减少脚本量。

### 2. 分类

- **有效等价类**：满足需求的数据集合
- **无效等价类**：不满足需求的数据集合

### 3. 设计步骤

- **明确需求**
  - 手工测试做法：阅读需求文档，分析输入条件、规则。
  - **增强做法**：同时阅读接口文档、代码逻辑，理解输入约束在代码中的实现
- **划分等价类**
  - 手工测试做法：考虑**长度、类型、规则、是否为空**等维度，列出有效和无效等价类。
  - **增强做法**：用思维导图整理，同时考虑**代码分支覆盖**（如if-else对应的等价类）
- **提取代表值**
  - 手工测试做法：**提取代表值，编写测试用例**。
  - **增强做法**：将代表值存入数据文件（Excel/JSON/YAML），实现数据驱动
- **编写用例**
  - 手工测试做法：写Excel用例
  - **增强做法**：编写pytest脚本，用`@pytest.mark.parametrize`注入数据

- **重要原则**：
  - 一条**有效用例**应尽可能覆盖多个有效等价类（减少用例数）。
  - 一条**无效用例**只覆盖一个无效等价类（防止多个无效条件互相干扰，无法定位问题）：在自动化中，每个无效数据应单独一条用例，便于定位失败原因。pytest中可分别参数化。

### 4. 案例

- **需求1**：验证QQ账号的合法性，要求6~10位自然数。
  - **长度**
    - 有效等价类：6-10位
    - 无效等价类：<6位、>10位
  - **类型**
    - 有效等价类：数字字符
    - 无效等价类：非数字字符（字母、特殊符号）、小数、负数
  - **空值**
    - 有效等价类：/
    - 无效等价类：空字符串、null（如果API允许）
  - **已存在**
    - 有效等价类：新账号（不存在）
    - 无效等价类：已存在的账号（业务规则）
  - **敏感词**
    - 有效等价类：无敏感词
    - 无效等价类：包含敏感词（如admin、root）
  - **代表值示例**
    - 有效：`123456`（6位）、`1234567890`（10位）、`12345678`（8位）——可选一个代表。
    - 无效：`12345`（长度不足）、`12345678901`（超长）、`abcdef`（非数字）、`12.345`（小数）。
    - **补充**：除了显式的输入规则，还要考虑**隐含的等价类**，如"账号是否已存在"、"是否包含敏感词"等，这些属于业务规则层面的等价类。

- **需求2**：验证某城市电话号码正确性。
  - **要求**
    - 区号：空或者是三位数字
    - 前缀码：非0且非1开头的三位数字
    - 后缀码：四位数字
  - **长度**
    - 区号：有效 空/3位；无效 2位
    - 前缀码：有效 3位；无效 2位
    - 后缀码：有效 4位；无效 2位
  - **类型**
    - 区号：有效 数字；无效 非数字
    - 前缀码：有效 数字；无效 非数字
    - 后缀码：有效 数字；无效 非数字
  - **规则**
    - 区号：有效 /；无效 /
    - 前缀码：有效 2开头；无效 0开头、1开头
    - 后缀码：有效 /；无效 /
  - **用例组合**
    - 正向2条：区号空+前缀码2开头的三位数字+4位数字；区号3位+前缀码2开头的三位数字+4位数字
    - 逆向8条
    - **要点**：正向一次尽可能覆盖多个正确数据组合，逆向一次只能覆盖一个错误。

### 5. 使用场景

- 针对需要有大量测试数据输入，但是无法穷举测试的地方。输入框、下拉列表、单选/复选框等有明确输入范围的控件。
### 6. 例题
- **Q**：等价类划分时，如何确保覆盖了所有重要的无效类？
- **A**：我会从以下几个维度系统思考：
    - 数据类型：字符串、数字、布尔、数组、对象等
    - 数据格式：邮箱、手机号、身份证等格式错误
    - 业务规则：重复、不存在、权限不足等
    - 边界：空值、null、超长、特殊字符
    - 组合：多个无效条件（但用例中只覆盖一个）
