## Web 前端三大核心技术

- **HTML**
  - 基础作用：结构
  - **实战要点**：元素定位的根基。所有Selenium/Playwright的定位策略（ID、XPath、CSS Selector）都基于HTML
  - **面试话术**："我通过分析HTML结构，选择最稳定的属性（如ID或data-*）进行定位，避免使用动态class。"
- **CSS**
  - 基础作用：样式
  - **实战要点**：处理隐藏元素、动态样式。比如元素`display:none`时无法点击，需先修改样式或等待可见
  - **面试话术**："遇到元素被遮挡或不可见时，我会检查CSS属性，用JS修改或等待样式变化。"
- **JavaScript**
  - 基础作用：行为
  - **实战要点**：处理异步加载、事件触发。很多点击事件是JS绑定的，需等待JS执行完成
  - **面试话术**："我常用`execute_script`直接调用JS方法，或通过等待元素状态（如`document.readyState`）确保页面加载完成。"

- **Q**：你在自动化测试中，遇到过哪些与前端技术相关的问题？**A**：
  - **元素被遮挡**：发现是CSS的`z-index`问题，用JS修改样式或点击父元素。
  - **点击无效**：因为按钮绑定的是JS事件，用`execute_script`直接触发事件。
  - **异步加载**：等待特定元素出现或JS变量变化，而不是固定时间sleep。
  - 理解前端技术让我能快速定位问题根源，而不是盲目改脚本。

## HTML 骨架结构
### 骨架代码
	```
	<!DOCTYPE html>          <!-- 文档类型声明，告诉浏览器使用 HTML5 解析 -->
	<html lang="en">         <!-- 根标签，lang 属性声明页面语言 -->
	<head>                   <!-- 头部：定义元数据、标题、样式、脚本等 -->
		<meta charset="UTF-8">
		<title>页面标题</title>
	</head>
	<body>                   <!-- 主体：页面可见内容 -->
		...
	</body>
	</html>
	```
### 补充说明
- **补充说明**：
  - `<!DOCTYPE html>` 不是 HTML 标签，而是一个声明，必须放在第一行。
  - `<head>` 中的 `<meta>` 标签对 SEO、编码、响应式等很重要，自动化测试中可能通过 `<meta>` 获取页面信息（如编码，处理中文乱码），通过`<title>`验证页面跳转正确。
  - `<body>` 是自动化测试的主要操作区域。

## HTML 标签与定位

### 1. 标签分类

- **单标签（空标签）**：`<br/>`、`<img/>`、`<input/>`、`<hr/>` 等。
- **实战要点**：注意没有文本内容，只能通过属性定位
- **双标签**：`<b>内容</b>`、`<div></div>`、`<p></p>` 等。
- **实战要点**：可利用文本内容（XPath的`text()`）定位，但文本易变，不推荐

### 2. 标签属性（定位优先级）

- 格式：`<标签名 属性名="属性值">内容</标签名>`
- 例如：`<a href="https://www.jd.com" target="_blank">京东</a>`
- 常用全局属性（几乎所有标签都支持）：
  - `id`：元素的唯一标识（自动化定位首选，应保持唯一且稳定）
  - `class`：元素的类名（用于 CSS 样式，也可用于定位，通常一个元素有多个 class）
  - `name`：表单元素名称（提交数据时的 key）
  - `style`：内联样式
  - `data-*`：自定义属性（常用来存储额外信息，也可用于定位）
- 定位优先级：
  - **id（⭐⭐⭐）**
    - 优点：唯一、稳定、速度快
    - 缺点：开发可能不写或动态生成
    - 示例：`find_element(By.ID, "username")`
  - **name（⭐⭐）**
    - 优点：表单元素常用
    - 缺点：可能重复
    - 示例：`find_element(By.NAME, "username")`
  - **class（⭐）**
    - 优点：可组合定位
    - 缺点：常变化、多个值
    - 示例：`find_element(By.CLASS_NAME, "btn-primary")`
  - **tag name（⚠️）**
    - 优点：简单
    - 缺点：不唯一，极少单独用
    - 示例：`find_elements(By.TAG_NAME, "input")`
  - **link text（⚠️）**
    - 优点：对超链接直观
    - 缺点：文本易变、国际化问题
    - 示例：`find_element(By.LINK_TEXT, "登录")`
- **核心原则**：
  - 优先使用ID，其次`data-*`，最后才是XPath/CSS组合。
  - 永远不要依赖动态属性（如随机生成的class、自动递增的id）。

- **Q**：如果页面元素没有ID，你怎么定位？**A**：我会按顺序尝试：
  - 看有没有`data-testid`或`name`等稳定属性。
  - 用CSS Selector组合稳定属性（如`[type='submit']`）。
  - 用XPath通过文本或位置（但要评估稳定性，文本易变）。
  - 如果都不行，推动开发添加`data-testid`属性，这是最彻底的解决方案。

### 3. 常用标签详解


#### 说明
- **标题标签**：`<h1>标题</h6>`
- **段落标签**：`<p>段落</p>`
- **超链接标签**：`<a href = "http://www.baidu.com" target = "_blank" >百度</a>`  
- **超链接标签**定位方式：
    - 通过链接文本（简单但易变）：`driver.find_element(By.LINK_TEXT, "百度").click()`
    - 通过部分文本（适合长文本）：`driver.find_element(By.PARTIAL_LINK_TEXT, "百").click()`
    - 更推荐：通过href属性（如果稳定）：`driver.find_element(By.XPATH, "//a[@href='http://www.baidu.com']").click()`
- **图片标签**：`<img src = "02.jpg" width="200px" height="200px" title="希望在田野" alt="照片"/>`
  - 检查点：
    - 图片是否加载成功（检查`naturalWidth` > 0）
    - 鼠标悬停时`title`是否正确显示
    - `alt`属性在图片加载失败时的占位文本
#### 自动化示例
    ```
    img = driver.find_element(By.XPATH, "//img[@title='希望在田野']")
    # 检查图片是否加载
    is_loaded = driver.execute_script("return arguments[0].complete && arguments[0].naturalWidth > 0", img)
    assert is_loaded
    # 检查alt属性
    assert img.get_attribute("alt") == "照片"
    ```
#### 空格与换行

#### 说明
- **空格与换行**：`&nbsp;` 空格，`<br/>` 换行
- **布局标签**：页面布局使用，常用div和span
  - `<div>`块级元素，常用于分组，定位复杂元素时需理解其层级关系
  - `<span>`内联元素，常用于文本片段
- **列表标签**：li
  - 有序：`<ol><li>杭州</li><li>深圳</li></ol>`
  - 无序：`<ul><li>杭州</li><li>深圳</li></ul>`
- **表单标签**：
  - 用于收集用户输入数据并提交到服务器的HTML元素组合
  - 页面占比：表单元素（输入框+按钮）约占网页可见元素的85%
  - action的method方法：
    - **get**
      - 参数可见性：所有参数明文显示在URL中
      - 传输速度：执行速度快
      - 数据限制：提交内容长度有限制（不同浏览器限制不同）
      - 适用场景：适合查询等非敏感信息传输，只应当用于取回数据
    - **post**
      - 参数可见性：参数不会显示在URL中
      - 传输速度：相对较慢
      - 数据限制：提交内容长度无限制
      - 安全性：虽然比GET更安全，但仍需配合加密措施
      - 适用场景：适合登录等敏感信息传输
#### 表单示例
    ```
    <form action="index.html" method="">
      用户名：
      <input type="text"/>
      <br/>
      密码：
      <input type="password"/>
      <br/>
      性别：
       <input type="radio" name="render"/>男
       <input type="radio" name="render"/>女
       <br/>
      爱好：
      <input type="checkbox"/>挣钱
      <input type="checkbox"/>吃饭
      <br/>
      <input type="submit"/>
      <input type="reset"/>
      <input type="button" value="普通按钮"/>
    </form>
    ```

### 4. 常用表单元素定位


#### 说明
- **文本输入框**
  - HTML示例：`<input type="text"/>`
  - 自动化操作：`send_keys("内容")`
- **密码框**
  - HTML示例：`<input type="password"/>`
  - 自动化操作：`send_keys("密码")`
- **单选框**
  - HTML示例：`<input type="radio" name="gender"/>`
  - 自动化操作：点击元素：`click()`
- **复选框**
  - HTML示例：`<input type="checkbox"/>`
  - 自动化操作：先判断是否已选：`is_selected()`，再点击
- **提交按钮**
  - HTML示例：`<input type="submit"/>`
  - 自动化操作：`click()` 或直接提交表单：`form.submit()`
- **普通按钮**
  - HTML示例：`<input type="button" value="普通按钮"/>`
  - 自动化操作：`click()`
- **下拉框**
  - HTML示例：`<select>`
  - 自动化操作：用`Select`类处理（后续章节详述）
- **Q**：如何处理表单中的验证码？**A**：
	- 测试环境：让开发屏蔽验证码或设置万能验证码。
	- 自动化：如果是简单图形验证码，尝试OCR识别；如果是短信验证码，可连接数据库或日志获取。
	- 最佳实践：推动测试环境关闭验证码，专注于业务逻辑测试。
- **Q**：如果表单提交后页面没有跳转（AJAX提交），如何验证成功
**A**：不等待页面加载，而是等待某个成功提示元素出现，或检查接口返回（如果可mock），或验证数据库数据变化。

### 5. 表单自动化完整示例

```
# 定位表单元素
username = driver.find_element(By.NAME, "username")
password = driver.find_element(By.NAME, "password")
gender_male = driver.find_element(By.XPATH, "//input[@name='gender' and @value='male']")
hobby = driver.find_element(By.XPATH, "//input[@value='coding']")
submit_btn = driver.find_element(By.XPATH, "//input[@type='submit']")
# 操作
username.send_keys("testuser")
password.send_keys("123456")
gender_male.click()
hobby.click()
submit_btn.click()
# 或者直接提交表单（如果有form）
form = driver.find_element(By.TAG_NAME, "form")
form.submit()  # 会触发表单提交，相当于点击提交按钮
```
