## 基本使用

- **角色**：最流行的接口测试工具，GUI 操作，一条链路覆盖请求发送、断言、关联、参数化、测试报告。
- **发送请求**：选择方法(GET/POST/PUT/DELETE) + 填 URL + 配置 Params/Headers/Body → 点 Send。
- **Body 类型**
  - **none**：无请求体，GET 查询类用
  - **form-data**：multipart 表单，可同时传文本和文件
  - **x-www-form-urlencoded**：普通表单键值对
  - **raw**：原始报文，JSON 提交最常用(选 JSON 格式)
  - **binary**：纯二进制文件上传
- **响应查看**：顶部显示状态码、响应时间(ms)、响应大小；正文支持 Pretty / Raw / Preview 三种视图。
- **实战要点**：Postman 里能发的请求，换成 requests 代码就是接口自动化；两者技能同源。

## 集合与环境

- **集合**：一组接口用例的容器，可按模块建文件夹分组；支持导入/导出/分享，团队协作靠它。
- **Collection Runner**：选中集合一键批量运行，可配迭代次数、延迟、数据文件。
- **环境**：Environment 保存一组变量(如 dev/test/prod 不同的 base_url)，一键切换环境。
- **变量引用**：`{{变量名}}`，请求 URL、Headers、Body 里都能用。
- **变量作用域(4 级)**
  - **全局(Global)**：所有集合、所有环境可用
  - **环境(Environment)**：当前环境内可用
  - **集合(Collection)**：仅当前集合可用
  - **数据(Data)**：参数化数据文件提供，仅当前迭代可用
- **优先级**：Data > Collection > Environment > Global，同名变量高优先级覆盖低优先级。
- **面试话术**：变量作用域是 Postman 高频考点——先明确"这个变量该放全局/环境/集合"，再决定在哪定义。


## 断言、关联与前置脚本

### 断言（Tests）

#### 作用

- 请求返回后执行，验证响应是否符合预期，对应 Python 的 assert。

#### 常用断言


#### 说明
- 状态码、响应体包含、JSON 字段值、响应时间、响应头。

#### 示例代码

```
pm.test("Status code is 200", function () {

	pm.response.to.have.status(200);

});

pm.test("Body matches string", function () {

	pm.expect(pm.response.text()).to.include(10000);

});

pm.test("code", function () {

	var jsonData = pm.response.json();

	pm.expect(jsonData.code).to.eql(10000);

});

// 断言响应时间
pm.test("Response time < 500ms", () => {
    pm.expect(pm.response.responseTime).to.be.below(500);
});

// 断言响应头
pm.test("Content-Type is JSON", () => {
    pm.response.to.have.header("Content-Type", "application/json");
});
```

#### 实战要点


#### 说明
- 断言的"校验三层"(状态码/业务码/关键字段)在 Postman 里同样适用，别只断状态码。

### 关联

#### 作用


#### 说明
- 把前一个请求响应中的动态值(token、订单号)提取出来，供后续请求使用。

#### 示例代码

```
var jsonData = pm.response.json()

pm.environment.set("glb_token",jsonData.message)

pm.environment.set("env_token",jsonData.data)

{{调用}}
```

#### 存储位置

- `pm.environment.set("key", value)`：存到当前环境
- `pm.globals.set("key", value)`：存到全局
- `pm.collectionVariables.set("key", value)`：存到当前集合

#### 引用与代码对应

- **引用**：后续请求 `{{token}}` 直接使用。
- **对应代码**：`resp.json()["data"]["token"]` 存变量，下一请求 headers 携带。

### 前置脚本（Pre-request Script）

- **作用**：请求**发送前**执行，用于生成签名、时间戳、动态参数、环境准备。
- **与 Tests 的区别**：Pre-request 在请求前跑，Tests 在响应后跑。
- **常用动态变量**：`{{$timestamp}}` 时间戳、`{{$randomInt}}` 随机整数、`{{$guid}}` 唯一 ID。
- **典型场景**：接口要求 `timestamp + sign` 签名，前置脚本里生成并写入环境变量。

## 鉴权设置

- **位置**：请求的 Authorization 页签，Type 下拉选择。
- **常用类型**
  - **No Auth**：无鉴权
  - **Basic Auth**：用户名密码(base64)
  - **Bearer Token**：`Authorization: Bearer <token>`，JWT 接口常用
  - **API Key**：请求头/参数携带密钥
- **对应代码**：`requests.get(url, headers={"Authorization": f"Bearer {token}"})`。


## 参数化、Mock 与测试报告

### 参数化

- 实现测试数据和脚本分离。测试数据保存在**数据文件中单独维护**，引用数据文件**实现脚本迭代调用**。
- **数据文件**
  - **CSV**
    - 优点：数据组织格式简单
    - 缺点：
      - 无法测试 bool 类型，postman 读取 csv 时将所有非数值类型自动添加""成为字符串
      - 无法存储复杂数据类型(元组、列表、字典)
      - 不能实现参数测试
    - 应用场景：数据量较大且数据组织格式简单
  - **JSON**：可存复杂数据类型，适合结构化测试数据
- **读取数据文件**
  - 请求参数中使用 `{{username}}` 引用
  - js 代码中使用 `data.username`
- **集合和环境的导入导出**：数据文件配套集合一起分发。
- **数据文件命名规范**：`模块名_接口名_data.csv`。

### Mock Server

- **作用**：后端接口未就绪时，按预设规则模拟返回数据。
- **场景**：前后端并行开发，前端/测试先用 Mock 数据联调；接口测试可先跑通流程。
- **实战要点**：Mock 是接口测试必备技能——被测服务依赖的下游接口不稳定时，用 Mock 隔离。

### 生成测试报告

- **工具**：newman(Postman 的命令行版)，CI 集成用。
- **命令**：`newman run collections [-e environments] [-d data] -r htmlextra --reporter-htmlextra-export report.html`。
- **对应代码**：pytest + Allure 生成的 HTML 报告，概念同源。

## 面试高频题

- **Q**：Postman 怎么实现接口关联？**A**：Tests 里用 `pm.environment.set("token", jsonData.data)` 存变量，后续请求 `{{token}}` 引用。
- **Q**：Postman 变量作用域有哪些？**A**：全局、环境、集合、数据文件四级，优先级 Data > Collection > Environment > Global。
- **Q**：POST 提交 JSON 选哪种 Body？**A**：raw，并设置格式为 JSON；表单用 x-www-form-urlencoded，传文件用 form-data。
- **Q**：CSV 和 JSON 数据文件怎么选？**A**：数据量大且结构简单用 CSV；要存 bool/复杂类型用 JSON。
- **Q**：怎么生成接口测试报告？**A**：用 newman 命令行运行集合，`-r htmlextra` 输出 HTML 报告，可接 CI。
- **Q**：后端没开发完怎么测？**A**：用 Postman Mock Server 模拟接口返回，先跑通流程再切真实接口。
