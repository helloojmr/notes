## 基本使用

### 请求方法

- `resp = requests.get(url)`：查询
- `resp = requests.post(url)`：新增/提交
- `resp = requests.put(url)`：整体更新
- `resp = requests.delete(url)`：删除
- 对应 Postman：方法下拉选同一个，接口文档里标什么方法就用什么方法。

### 常用参数

- `requests.请求方法(url, params={}, data={}, json={}, headers={}, cookies={}, files={}, timeout=N, verify=False)`
- **url**：接口地址
- **params**：GET 查询参数，自动拼到 URL 问号后
- **data**：POST 表单数据(`application/x-www-form-urlencoded`)
- **json**：POST JSON 数据(自动设置 `Content-Type: application/json`)
- **headers**：自定义请求头(Content-Type、Authorization 等)
- **cookies**：携带 Cookie
- **files**：文件上传
- **timeout**：超时时间(秒)，避免脚本卡死
- **verify=False**：跳过 SSL 证书校验(测试环境 https 用)
- **测开**：这几个参数就是 Postman 里 Params/Headers/Body 的可视化落点，一一对应。

### 响应对象

- `resp.status_code`：状态码，如 200 / 404 / 500
- `resp.text`：响应文本
- `resp.json()`：响应转字典(接口返回 JSON 时用)
- `resp.content`：二进制内容(下载文件用)
- `resp.headers`：响应头
- `resp.cookies`：服务器返回的 Cookie(RequestsCookieJar 对象)
- `resp.url`：最终请求的 URL(看重定向/参数拼接结果)
- `resp.encoding`：响应编码(乱码时改 UTF-8)
- `resp.elapsed`：请求耗时(性能分析用)
- `resp.raise_for_status()`：状态码非 2xx 时抛异常，代替手写 if 判断
- **面试话术**：响应对象属性是 requests 接口自动化的基本功，配合断言三板斧(状态码、业务码、字段)就是一套用例。

### 常用请求场景

#### GET 查询

```
resp = requests.get(
    "http://api.example.com/api/search",
    params={"keyword": "手机", "page": 1},
    timeout=5
)
print(resp.json())
```

#### POST JSON

```
resp = requests.post(
    "http://api.example.com/api/login",
    json={"username": "tom", "password": "123456"},
    timeout=5
)
assert resp.json()["code"] == 0
```

#### POST 表单

```
resp = requests.post(
    "http://api.example.com/api/order",
    data={"goodsId": 1, "num": 2}
)
```

#### 文件上传

```
files = {"file": open("C:/test/1.jpg", "rb")}
resp = requests.post("http://api.example.com/api/upload", files=files)
```

#### 自定义请求头

```
headers = {
    "Content-Type": "application/json",
    "Authorization": "Bearer " + token
}
resp = requests.get("http://api.example.com/api/orders", headers=headers)
```


## 会话与认证

### 会话保持（Session）

#### 作用

- 用 `requests.Session()` 自动管理 Cookie

#### 示例代码

```
session = requests.Session()

# 获取验证
resp_v = session.get(url='')

# 使用同一个 session 实例发送请求
resp = session.post(url='', data={k:v})

resp.url
resp.status_code
resp.cookies # RequestsCookieJar 对象
resp.headers
resp.text
resp.json()
```

#### 要点说明

- 使用同一个 `Session` 实例能确保 cookies 在两次请求间自动传递，这对于依赖 cookie 的会话管理至关重要。
- **关键**：这里的"session"是 `requests` 库的 **Session 对象**，它模拟了浏览器对 Cookie 的自动管理，与服务器端的"Session"概念不同，但两者配合使用——服务器端 Session 依赖 Cookie 传递 Session ID，而 `requests.Session` 负责在代码层面自动处理这些 Cookie。
- **对应 Postman/JMeter**：Postman 自动管 Cookie，JMeter 的 HTTP Cookie Manager，都是同一个 Session 思想的落地。

### Cookie 与认证

#### Cookie 概念

- 定义：针对 http 协议是无连接、**无状态**特性而设计的一种技术。在浏览器端存储的小型文本数据，由服务器通过 `Set-Cookie` 响应头发送给浏览器，之后浏览器每次请求都会自动携带该域下的 Cookie。
- 特点：
  - 默认大小 4kb
  - 存储用户临时的不敏感信息
  - cookie 中的数据可以随意访问，存储的数据类型受浏览器限制

#### 两种认证方式

- **token 认证(如 JWT)**
  - 服务器生成一个加密的 Token(包含用户信息、过期时间等)，发送给客户端。
  - 客户端后续请求将 Token 放在请求头(如 `Authorization`)中。
  - 服务器验证 Token 的合法性，无需在服务器端存储 Session 数据。
- **cookie + session 认证(最通用)**
  - 服务器为每个登录用户创建一个 Session(存储在服务器内存/数据库中)，里面保存用户的核心状态(如用户 ID、权限)。
  - 同时生成一个唯一的 Session ID，通过 Cookie 发送给浏览器(设置 `HttpOnly`、`Secure`、`SameSite` 等安全属性)。
  - 浏览器后续请求自动携带该 Cookie，服务器根据 Session ID 找到对应的 Session 数据，从而识别用户。
  - 优点：用户数据保存在服务器，更安全；Cookie 只存一个无意义的 ID。

#### Cookie 与 Session 对比

- **存储位置**
  - Cookie：**客户端**(浏览器)
  - Session：**服务器端**(内存、数据库、文件)
- **存储内容**
  - Cookie：通常是 ID 或少量加密数据
  - Session：丰富的用户状态信息(用户对象、权限列表等)
- **安全性**
  - Cookie：**相对较低**，存在客户端可能被窃取或篡改
  - Session：**相对较高**，关键数据保存在服务器
- **性能影响**
  - Cookie：几乎无影响，数据在客户端
  - Session：**有影响**，大量用户时占用服务器资源
- **跨域支持**
  - Cookie：可控制(同源策略，可设置 `Domain`)
  - Session：默认不支持，需额外方案(如集中 Session 存储)
- **数据大小**
  - Cookie：单个 ≤ 4KB，每域名下数量有限
  - Session：理论上只受服务器资源限制

### 代码携带 Cookie 认证

#### 手动携带

- 手动处理 Cookie

#### 示例代码

```
resp = requests.get(url)          # 第一次请求，服务器可能返回 Set-Cookie
cookie_jar = resp.cookies          # 拿到服务器返回的 Cookies(RequestsCookieJar 对象)

# 后续请求手动携带 Cookies
resp2 = requests.post(url2, cookies=cookie_jar)
```

#### 使用建议

- 优先用 Session 自动管理(见"会话保持"节)，手动方式了解即可。


## 异常与常用技巧

### 超时与异常处理

- **timeout**：不设超时，服务端无响应时脚本会一直挂住，接口自动化必加。
- **timeout 传元组**：`timeout=(3, 5)` 表示连接超时 3 秒、读取超时 5 秒。

#### 异常捕获示例

```
try:
    resp = requests.get(url, timeout=5)
    resp.raise_for_status()   # 非 2xx 抛 HTTPError
except requests.exceptions.ConnectTimeout:
    print("连接超时")
except requests.exceptions.ReadTimeout:
    print("读取超时")
except requests.exceptions.RequestException as e:
    print("其他请求异常:", e)
```

#### 面试话术

- 超时 + 异常捕获是接口脚本稳定性的第一道保障，不处理的脚本一跑就崩。

### 常见问题与技巧

#### 响应乱码

- 现象：接口返回中文显示乱码。
- 解决：先 `resp.encoding = "utf-8"` 再取 `resp.text`；或在请求头带 `Accept-Encoding`。

#### 跳过 SSL 校验

- 场景：测试环境 https 自签名证书，`verify=True`(默认)会报证书错误。
- 解决：`requests.get(url, verify=False)`，并配合 `warnings.filterwarnings("ignore")` 忽略告警。

#### 简单重试

- 场景：网络抖动导致偶发失败。
- 实现：循环重试 N 次，失败间隔再试；进阶用 urllib3 的 Retry 机制(了解)。

#### 代理抓包

- 配合 Fiddler/Charles 抓包调试：`proxies = {"http": "http://127.0.0.1:8888", "https": "http://127.0.0.1:8888"}`。

## 面试高频题

- **Q**：requests 的 data 和 json 参数有什么区别？**A**：data 发表单(`application/x-www-form-urlencoded`)，json 发 JSON 并自动设置 `Content-Type: application/json`；后端解析方式不同。
- **Q**：Session 对象有什么用？**A**：自动管理 Cookie 保持会话，模拟浏览器；登录后业务接口连续请求不丢失登录态。
- **Q**：接口响应中文乱码怎么办？**A**：设置 `resp.encoding = "utf-8"` 后再取 text；检查服务端返回的编码与 charset 是否一致。
- **Q**：接口请求超时怎么处理？**A**：设置 `timeout`(可传 `(connect, read)` 元组)，用 try-except 捕获 ConnectTimeout/ReadTimeout，加重试。
- **Q**：文件上传接口怎么写？**A**：`files = {"file": open("1.jpg", "rb")}`，`requests.post(url, files=files)`，自动走 multipart。
- **Q**：https 自签名证书报错怎么办？**A**：`verify=False` 跳过校验(仅测试环境)，生产环境必须校验证书。
