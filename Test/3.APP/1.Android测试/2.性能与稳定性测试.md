## 性能测试核心维度

- **CPU**
  - 测试关注点：占用率过高、持续飙高、多核负载不均
  - 常用工具/命令：`adb shell top`
  - `adb shell dumpsys cpuinfo`
- **GPU**
  - 测试关注点：渲染帧率、掉帧、过度绘制
  - 常用工具/命令：`adb shell dumpsys gfxinfo`、Profile GPU Rendering（开发者选项）
  - UI 自动化中可结合帧率判断页面滑动是否流畅
- **内存**
  - 测试关注点：内存泄漏（Memory Leak）、内存溢出（OOM）
  - 常用工具/命令：`adb shell dumpsys meminfo`、LeakCanary
  - 重点关注反复进入退出同一页面后内存是否持续增长
- **流量**
  - 测试关注点：上行/下行流量消耗
  - 常用工具/命令：`cat /proc/uid_stat/[userId]/tcp_snd/rcv`
  - 对比不同场景（首次启动、后台、刷新）的流量消耗是否符合预期
- **电量**
  - 测试关注点：耗电过快、后台异常唤醒
  - 常用工具/命令：`adb shell dumpsys batterystats`、Battery Historian
  - 需关注长时间待机或特定场景（如定位、播放）的耗电情况
- **稳定性**
  - 测试关注点：长时间运行是否崩溃、无响应
  - 常用工具/命令：Monkey、Maxim、UiAutomator
  - 自动化测试中可集成 Monkey 作为稳定性验收环节

- 性能测试不是一次性活动，应纳入 CI/CD 流水线，每次版本构建后自动执行核心性能场景。
- 性能测试结果需要建立基线（baseline），对比版本间的变化趋势。
- **Q**：如何定位内存泄漏？**A**：1. 用 `adb shell dumpsys meminfo` 观察反复进出页面后内存是否回降；2. 结合 LeakCanary 工具自动检测；3. 用 MAT 或 Profiler 分析 heap dump。

## 稳定性测试(Monkey)

### 基本命令格式
```
adb shell monkey -p 包名 -v 事件数 > log.txt
```

### 常用参数
- **-p 包名**：指定测试的包名（可多个 -p）
- **-v**：日志级别（-v -v -v 最详细）
- **--throttle 毫秒**：事件间隔，避免操作太快导致卡死
- **--pct-touch 百分比**：触摸事件占比
- **--pct-motion 百分比**：滑动事件占比
- **--pct-nav 百分比**：导航事件占比
- **--pct-appswitch 百分比**：切换应用占比
- **--pct-anyevent 百分比**：其他事件占比
- **-s 种子值**：指定随机数种子，可复现相同事件序列
- **--ignore-crashes**：遇到崩溃不停止，继续执行
- **--ignore-timeouts**：遇到无响应不停止
- **--kill-process-after-error**：发生错误后杀掉进程

### 稳定性测试常用配置
```
adb shell monkey -p com.example.app --throttle 300 \
--pct-touch 40 --pct-motion 25 --pct-nav 10 \
--pct-appswitch 15 --pct-anyevent 10 \
--ignore-crashes --ignore-timeouts \
-v -v -v 10000 > monkey_test.log
```

### 使用注意事项
- Monkey 主要用于发现随机崩溃和 ANR，但无法覆盖业务逻辑缺陷。
  - 执行前需确保应用处于可测试状态（已登录、在首页）。
  - 日志分析重点关注：`CRASH`、`ANR`、`NOT RESPONDING` 等关键字。
  - 可用 `-s` 种子值复现问题，便于开发定位。
- **Q**：Monkey 执行后发现崩溃，如何定位？**A**：1. 从日志中找到崩溃时的堆栈信息；2. 用相同的种子值复现；3. 结合 `adb logcat` 查看系统日志；4. 如果是 ANR，抓取 `/data/anr/traces.txt` 分析。
