## unittest 核心与 TestCase

### 框架测试流程
- **组织用例**
  - 手工测试脚本的问题：函数散乱，难以管理
  - unittest解决方案：TestCase类组织相关用例
- **批量执行**
  - 手工测试脚本的问题：手动逐个调用
  - unittest解决方案：TestSuite + TestRunner批量运行
- **数据准备与清理**
  - 手工测试脚本的问题：每个用例重复写setup/teardown
  - unittest解决方案：Fixture机制自动执行
- **结果判断**
  - 手工测试脚本的问题：if语句判断，可读性差
  - unittest解决方案：丰富的断言方法
- **报告生成**
  - 手工测试脚本的问题：自己拼凑输出
  - unittest解决方案：HTMLTestReport生成专业报告
- **数据驱动**
  - 手工测试脚本的问题：代码与数据耦合
  - unittest解决方案：parameterized实现数据分离

- **面试官常问**：“你平时用unittest还是pytest？为什么？”
**回答框架**：“我两种都用过。unittest是**Python内置框架**，无需安装，适合简单的单元测试和初学者。pytest更简洁强大，支持更丰富的断言、插件生态更好，我在实际项目中使用pytest居多。但在一些遗留项目或团队规范中，也会使用unittest。两者核心思想相通，掌握了unittest再学pytest很容易。”

### 框架组件

#### 说明
- **TestCase**
  - 作用：测试用例类，继承自`unittest.TestCase`
  - 关键点：方法必须以`test_`开头
- **TestSuite**
  - 作用：测试套件，组织多个用例
  - 关键点：可添加TestCase或模块
- **TestRunner**
  - 作用：执行测试，输出结果
  - 关键点：`TextTestRunner`文本结果，`HTMLTestRunner`HTML报告
- **TestLoader**
  - 作用：自动加载用例到套件
  - 关键点：`discover()`按规则发现用例
- **Fixture**
  - 作用：测试脚手架（前置/后置）
  - 关键点：方法级、类级、模块级

### TestCase编写规范
#### 基本规范
1. 基本规范

#### 说明
  - 测试类必须继承 `unittest.TestCase`。
  - 测试方法必须以 `test_` 开头。
  - 可以使用 `setUp()` 和 `tearDown()` 准备和清理资源。
#### 示例代码
```
import unittest

class TestMath(unittest.TestCase):
    def setUp(self):
        print("每个用例执行前")
        self.a = 10
        self.b = 5

    def tearDown(self):
        print("每个用例执行后")

    def test_add(self):
        result = self.a + self.b
        self.assertEqual(result, 15)

    def test_sub(self):
        result = self.a - self.b
        self.assertEqual(result, 5)
```
#### 执行顺序与结果
2. 执行顺序
  - 默认按方法名的**ASCII码顺序**执行，不是代码书写顺序。
  - 可以通过命名控制顺序：`test_01_add`、`test_02_sub`。
3. 测试结果标识
  - `.`：通过（pass）
  - `F`：失败（fail，断言没通过）
  - `E`：错误（error，代码本身出错)
