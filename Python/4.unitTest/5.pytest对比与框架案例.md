## unittest 与 pytest 对比（面试加分）

- **安装**：unittest 内置，无需安装；pytest 需要安装 `pip install pytest`
- **用例编写**：unittest 必须继承 TestCase，方法以 test_ 开头；pytest 函数以 test_ 开头即可，无需继承
- **断言**：unittest 多种 assertXXX 方法；pytest 直接用 Python `assert`
- **Fixture**：unittest 用 setUp/tearDown，类级别用 @classmethod；pytest 用 `@pytest.fixture` 更灵活，作用域可配置
- **参数化**：unittest 需第三方库 parameterized；pytest 内置 `@pytest.mark.parametrize`
- **插件生态**：unittest 较少；pytest 丰富（pytest-html、pytest-xdist 等）
- **执行**：unittest 用 TestSuite + TestRunner；pytest 命令行直接运行
- **兼容性**：unittest 不能直接运行 pytest 用例；pytest 兼容 unittest 用例（用 pytest 运行）

## 面试高频题


### 说明
- **Q**：`setUp()` 和 `setUpClass()` 的区别？**A**：`setUp()` 每条用例执行前运行一次，`setUpClass()` 整个测试类只运行一次，且必须用 `@classmethod` 装饰。
- **Q**：如何控制测试用例的执行顺序？**A**：默认按方法名 ASCII 顺序执行。可通过命名如 `test_01_add`、`test_02_sub` 控制，或使用 `TestSuite` 的 `addTest` 按添加顺序执行。
- **Q**：如何跳过某些测试用例？**A**：使用 `@unittest.skip`、`@unittest.skipIf`、`@unittest.skipUnless` 装饰器。
- **Q**：unittest 如何实现参数化？**A**：需要安装第三方库 `parameterized`，使用 `@parameterized.expand(data)` 装饰测试方法。
- **Q**：如何生成 HTML 测试报告？**A**：使用 `HTMLTestRunner` 或 `HTMLTestReport`，通过自定义 TestRunner 运行测试套件并写入文件。
- **Q**：`assertEqual` 和 `assertIn` 的区别？**A**：`assertEqual` 判断两个值是否相等，`assertIn` 判断第一个值是否在第二个容器中（如列表、字符串）。
- **Q**：unittest 如何实现测试数据与代码分离？**A**：将测试数据存放到外部文件（如 JSON、YAML、Excel），通过读取文件在测试方法中获取数据，结合 `parameterized` 实现数据驱动。
- **Q**：`TestLoader` 的作用？**A**：自动发现指定目录下符合条件的测试用例，加载到 TestSuite 中，常用 `discover()` 方法。
- **Q**：如何测试期望抛出异常的场景？**A**：使用 `assertRaises` 上下文管理器：
### 示例
```
with self.assertRaises(ValueError):
    function_that_should_raise()
```
### 要点问答
- **Q**：unittest 和 pytest 你更推荐用哪个？**A**：pytest 更简洁强大，插件丰富，适合新项目；unittest 内置，适合简单场景或维护老项目。
