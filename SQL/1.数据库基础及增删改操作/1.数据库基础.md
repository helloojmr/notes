## 数据库基本概念

- 行、列、表、库
- **测试数据准备**：在用例执行前，向数据库插入测试数据（如用户、订单）
- **结果校验**：断言时查询数据库，验证数据是否正确写入或更新
- **环境清理**：测试完成后删除产生的垃圾数据，保证环境干净
- **问题排查**：通过数据库直接修改数据，绕过 UI 触发特定状态（如订单状态）
- **性能测试**：监控数据库连接数、慢查询等

- **Q**：你在自动化测试中如何管理测试数据？**A**：通常会在测试用例前置条件中，通过 SQL 向数据库插入所需数据，测试完成后在清理阶段删除这些数据。对于复杂场景，会使用数据工厂模式，封装数据准备函数。同时，利用事务控制，在测试结束时回滚，避免污染环境。

## SQL 语言分类

- **DQL**（Data Query Language）：数据查询，重点掌握内容
  - 示例关键词：SELECT
- **DML**（Data Manipulation Language）：数据操作，包括插入、更新、删除
  - 示例关键词：INSERT, UPDATE, DELETE
- **DDL**（Data Definition Language）：定义数据库对象（如创建/删除数据库、表）
  - 示例关键词：CREATE, DROP
- **DCL**（Data Control Language）：权限控制
  - 示例关键词：GRANT, REVOKE
- **TPL**（Transaction Processing Language）：事务控制
  - 示例关键词：COMMIT, ROLLBACK

  - **-h**：主机地址，省略表示本机（localhost）
  - **-P**：端口，默认 3306（注意是大写 P）

  - **-p**：密码，可直接跟在 -p 后（无空格）或交互式输入（更安全）

## 常用数据类型

- **int**
  - 描述：整数
  - 年龄、数量、ID
- **bigint**
  - 描述：长整数
  - 订单号、时间戳（毫秒）
- **decimal(m,d)**
  - 描述：定点小数，m 总位数，d 小数位
  - 金额、分数（如 decimal(10,2)）
- **varchar(n)**
  - 描述：可变长度字符串，n 最大字符数
  - 用户名、邮箱、地址
- **char(n)**
  - 描述：定长字符串，不足补空格
  - 固定编码（如性别：'M','F'）
- **datetime**
  - 描述：日期时间，格式 YYYY-MM-DD HH:MM:SS
  - 创建时间、更新时间
- **timestamp**
  - 描述：时间戳，受时区影响，范围 1970-2038
  - 记录最后修改时间
- **text**
  - 描述：长文本
  - 文章内容、备注
- **binary**
  - 描述：二进制数据
  - 图片、文件（很少直接存数据库）

- `varchar` 和 `char` 的选择：`varchar` 节省空间，`char` 适合定长数据且检索稍快。
- 金额字段必须用 `decimal`，不能用 `float`（浮点有精度丢失）。
- `datetime` 和 `timestamp`：`timestamp` 占用更少空间，但有 2038 年问题。

## 数据约束

- **PRIMARY KEY**
  - 作用：主键，唯一且非空，表中只能有一个
  - 示例：`id INT PRIMARY KEY AUTO_INCREMENT`
  - 测试数据插入时，主键可自增，无需指定
- **NOT NULL**
  - 作用：字段值不能为 NULL
  - 示例：`name VARCHAR(20) NOT NULL`
  - 测试时需注意，如果插入 NULL 会报错
- **UNIQUE**
  - 作用：字段值必须唯一
  - 示例：`phone VARCHAR(11) UNIQUE`
  - 准备数据时避免重复，否则插入失败
- **DEFAULT**
  - 作用：指定默认值
  - 示例：`status INT DEFAULT 0`
  - 测试时可利用默认值简化插入语句
- **FOREIGN KEY**
  - 作用：外键，关联另一张表的主键
  - 示例：`FOREIGN KEY (class_id) REFERENCES classes(id)`
  - 测试时注意依赖关系，插入子表数据前需保证父表存在对应记录

- **Q**：主键和唯一约束有什么区别？**A**：主键只能有一个，且自动为非空；唯一约束可以有多个，允许为空值（但只能有一个 NULL）。
- **Q**：外键在测试中可能会带来什么问题？**A**：外键约束会导致数据插入/删除顺序有依赖，自动化测试中可能因依赖关系导致操作失败。测试环境可考虑禁用外键检查（`SET FOREIGN_KEY_CHECKS=0;`），但要注意数据一致性。
- **补充概念**：NULL 表示"未知"，不参与计算；空字符串是长度为 0 的字符串。在条件判断中，`IS NULL` 和 `= ''` 不同。

## 命令行操作 MySQL

### 数据库操作
- **查看所有数据库**：`SHOW DATABASES;`
- **使用数据库**：`USE database_name;`
- **查看当前使用的数据库**：`SELECT DATABASE();`
- **创建数据库**（指定字符集，推荐 utf8mb4，支持 emoji）：`CREATE DATABASE database_name CHARSET=utf8mb4;`
- **删除数据库**：`DROP DATABASE database_name;`
- 字符集选择：`utf8mb4` 才是真正的 UTF-8（MySQL 的 utf8 只支持最多 3 字节，无法存 emoji）。
- 删除数据库是危险操作，生产环境慎用。

### 数据表操作
- **查看当前库所有表**：`SHOW TABLES;`
- **查看表结构**：`DESC table_name;`
- **查看表的创建语句**（可以看到完整的定义，包括字符集、引擎等）：`SHOW CREATE TABLE table_name;`
- 通过 `SHOW CREATE TABLE` 可以快速复制表结构，用于搭建测试环境。
