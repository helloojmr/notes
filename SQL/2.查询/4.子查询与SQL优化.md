## 子查询
### 基本概念

- 嵌入在其他查询语句中的 select 语句称为子查询，其他的查询语句称之为主查询
- 子查询辅助主查询，要么充当**条件**，要么充当**数据源**
- 子查询是一条完整的、可单独执行的 select 语句

### 充当条件

#### 标量子查询
- **标量子查询**：查询王昭君的成绩
  - `select * from scores where studentno=(select studentno from students where name='王昭君');`
#### 列子查询
- **列子查询**：查询 18 岁的学生的成绩（列结果）
  - `select score from scores where studentno in (select studentno from students where age=18);`
#### 行子查询
- **行子查询**：查询和王昭君同班、同龄的学生信息（行结果）
  - `select * from students where (class,age)=(select class,age from students where name='王昭君');`

### 充当数据源

- 查询数据库和系统测试的课程成绩：
  - `select co.name,scores.score from scores inner join (select * from courses where name in('数据库','系统测试')) as co on scores.courseno=co.courseno;`

### 特定关键字

#### in（范围匹配）
- **in 范围**：主查询 where 条件 in (列子查询)
  - `select score from scores where studentno in (select studentno from students where age=18);`
#### any | some（任意匹配）
- **any | some 任意**：主查询 where 列 = ANY(列子查询) 或 = SOME(列子查询)
  - `select score from scores where studentno = any(select studentno from students where age=18);`
#### all（全部匹配）
- **all 所有**：主查询 where 列 = ALL(列子查询)
  - `select score from scores where studentno not in (select studentno from students where age=18);`
  - `select score from scores where studentno != ALL(select studentno from students where age=18);`
#### 更多示例
- **大于平均年龄的学生**：`select * from students where age > (select avg(age) from students);`
- **年龄在 18-20 之间的学生的成绩**：
  - 充当数据源：`select * from scores inner join (select studentno from students where age between 18 and 20) as st on scores.studentno = st.studentno;`
  - 充当条件：`select * from scores where studentno in (select studentno from students where age between 18 and 20);`

- **Q**：IN 和 EXISTS 的区别？**A**：IN 先执行子查询，将结果集缓存，外层表逐条匹配，适合子查询结果集小的情况；EXISTS 对外层表逐条判断子查询是否有返回，适合外层表大、子查询快的情况。现代 MySQL 优化器可能将 IN 优化为 EXISTS，但理解原理有助于优化。
- **Q**：ANY 和 ALL 的用法举例？**A**：`WHERE age > ANY (SELECT age FROM ...)` 大于子查询中任意一个即可；`WHERE age > ALL (SELECT age FROM ...)` 大于子查询中所有值。
- **连接查询与子查询的对比**：连接查询通常效率高于子查询（尤其是多表关联时），但子查询更易读。具体场景具体分析，有时子查询能解决连接难以处理的问题。
- **Q**：内连接和左连接的区别？**A**：内连接只返回两表中匹配的行；左连接返回左表全部行，右表无匹配则补 NULL。

## SQL 面试高频题

### 基础概念题
- **Q**：SQL 的书写顺序和执行顺序分别是什么？**A**：书写顺序：SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT；执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。
- **Q**：`WHERE` 和 `HAVING` 的区别？**A**：WHERE 在分组前过滤行，不能使用聚合函数；HAVING 在分组后过滤组，可以使用聚合函数。
- **Q**：UNION 和 UNION ALL 的区别？**A**：UNION 会去重并排序，UNION ALL 直接合并所有结果，效率更高。如果确定没有重复，用 UNION ALL。
- **Q**：什么是笛卡尔积？如何避免？**A**：连接查询没有 ON 条件时，会产生两表所有行的组合（行数乘积）。必须使用 ON 或 WHERE 限定连接条件。

### 查询实现题
- **Q**：如何查询每个班级年龄最大的学生？**A**：
#### 答案示例
```
SELECT * FROM students
WHERE (class, age) IN (
    SELECT class, MAX(age) FROM students GROUP BY class
);
```
#### 其他实现题
- **Q**：查询重复数据（如姓名重复的学生）？**A**：`SELECT name, COUNT(*) FROM students GROUP BY name HAVING COUNT(*) > 1;`
- **Q**：如何随机抽取 N 条记录？**A**：`SELECT * FROM students ORDER BY RAND() LIMIT 5;`（注意：大表效率低，可用其他方式）

### 优化题
- **Q**：如何优化 `LIKE '%keyword%'` 的查询？**A**：这种查询无法使用索引，因为前导通配符。可考虑全文索引（FULLTEXT）或搜索引擎（如 Elasticsearch）。

## SQL 优化

### 索引优化
- 索引是提高查询速度的关键。
- 常用索引：主键索引（PRIMARY KEY）、唯一索引（UNIQUE）、普通索引（INDEX）。
- 对查询条件中的字段（WHERE、JOIN、ORDER BY）加索引。
- **为经常查询的字段加索引**：`CREATE INDEX idx_name ON students(name);`
- **复合索引**：`CREATE INDEX idx_class_age ON students(class, age);`

### 查询写法优化

#### 避免 SELECT *
- 只查询需要的字段，减少数据传输。

#### 避免在索引列上使用函数或运算
- 低效（使用了函数，索引失效）：`SELECT * FROM students WHERE YEAR(create_time) = 2025;`
- 高效（改写为范围查询）：`SELECT * FROM students WHERE create_time >= '2025-01-01' AND create_time < '2026-01-01';`

#### 用 EXPLAIN 分析 SQL
- `EXPLAIN SELECT ...` 查看执行计划，检查是否使用索引
- **应用**：在测试中如果发现某个查询很慢，可以用 EXPLAIN 分析，协助开发优化。
