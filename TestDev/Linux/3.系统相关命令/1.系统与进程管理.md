## 测试应用场景

- **reboot/shutdown**：测试环境重启、维护窗口操作
- **ps/kill**：查看服务进程、杀死异常进程
- **top**：监控系统负载，分析性能瓶颈
- **netstat/lsof**：检查端口占用，定位服务启动失败原因
- **head/tail**：查看日志，实时监控日志输出

- **Q**：当你在测试环境中发现某个服务无法启动，你会怎么排查？**A**：先用 `ps` 检查进程是否存在，用 `netstat` 看端口是否被占用，用 `tail` 查看日志错误信息，再用 `top` 看系统资源是否充足。如果进程僵死，用 `kill` 处理；如果端口冲突，用 `lsof` 找到占用进程并解决。

## 重启与关机（reboot / shutdown）

- **reboot**：重启
- **shutdown**：关机
  - `shutdown -r now`：重启时会给其他用户发送提示信息
  - `shutdown -h now`：立刻关机
  - `shutdown -h 20:25`：定时关机
  - `shutdown -h +10`：10 分钟后关机
- **注意事项**：
  - 重启前务必保存工作，通知团队。
  - 在生产环境谨慎使用，测试环境可用 `reboot` 快速恢复。
  - 查看上次重启时间：`who -b` 或 `last reboot`。
- **Q**：reboot 和 shutdown -r now 有什么区别？**A**：`reboot` 是立即重启的快捷方式，而 `shutdown -r now` 会先向所有登录用户发送警告信息，然后执行重启，更友好一些。在生产环境建议用 `shutdown` 给用户缓冲时间。

## 进程查看（ps）

- 查看系统进程：`ps -aux | grep '关键字'`
- `ps -aux` 显示所有用户的所有进程（a=所有用户，u=显示用户，x=显示无终端的进程）
- 常见配合：`ps -ef` 也是查看所有进程（标准格式）
- 参数
	- **-L**：显示线程（Java 应用排查有用），示例：`ps -Lf <PID>`
	- **-o**：自定义输出列，示例：`ps -eo pid,ppid,cmd,%cpu,%mem --sort=-%cpu`
	- **--forest**：树状显示进程关系，示例：`ps -aux --forest`
	- **-C**：按命令名查找，示例：`ps -C java`
- **找出占用 CPU 最高的进程**（按 CPU 降序显示前 10 个）：`ps -aux --sort=-%cpu | head -11`
或使用 top 的批处理模式：`top -b -n 1 | head -20`

- **Q**：如何查看某个进程的启动时间？**A**：`ps -p <PID> -o lstart`，或查看 `/proc/<PID>/` 目录的创建时间。
- **Q**：`ps -aux` 和 `ps -ef` 有什么区别？**A**：两者都能显示所有进程，但输出格式不同。`-aux` 是 BSD 风格，`-ef` 是 System V 风格。实际使用中功能等价，看个人习惯。

## 实时系统监控（top）

### 交互式快捷键
- **M（shift+m）**：按内存降序
- **P（shift+p）**：按 CPU 降序
- **1**：显示每个 CPU 核心的使用情况
- **q**：退出

### 进阶技巧
- **批处理模式**：`top -b -n 1 > top.log` 一次性输出到文件，用于监控脚本。
- **指定进程**：`top -p 1234,5678` 只监控指定 PID。
- **按用户过滤**：在 top 界面按 `u` 然后输入用户名。

### 定位 CPU 飙升问题
- **先用 top 找到高 CPU 进程 PID**：`top -b -n 1 | grep -E "PID|java"`（假设 java 进程）
- **用 top -H 查看该进程内的线程**：`top -H -p <PID>`
- **找到高 CPU 线程 TID，转 16 进制后用 jstack 分析**：`printf "%x\n" <TID>`

- **Q**：如何理解 load average（系统负载）？**A**：load average 是 1 分钟、5 分钟、15 分钟的平均活跃进程数。如果这个值长期超过 CPU 核心数，说明系统可能存在瓶颈。例如 4 核 CPU，load average >4 表示任务排队。

## 终止进程（kill）

- **强制杀死进程（SIGKILL）**：`kill -9 <PID>`
- **正常终止（SIGTERM，给进程清理机会）**：`kill -15 <PID>`
- **按名称杀死进程**：`pkill -f "python app.py"`
- **杀死所有相关进程**：`killall nginx`
- **发送信号重新加载配置**：`kill -HUP <PID>`
- **安全重启服务**（先发 TERM 给 10 秒保存，再强制杀）：`kill -15 <PID>` → `sleep 10` → `if ps -p <PID> > /dev/null; then kill -9 <PID>; fi`

- 进程号可以通过 ps 或者 netstat 等命令获取到
- **Q**：进程 kill 不掉怎么办？**A**：进程可能处于"不可中断睡眠"状态（D 状态），通常是在等待 I/O。此时无法响应任何信号，只能重启系统或等待 I/O 完成。

## 跟踪系统调用（strace）

- **跟踪进程的所有系统调用**：`strace -p <PID>`
- **跟踪新启动的命令**：`strace -f -o output.log command`
- **统计系统调用耗时**：`strace -c -p <PID>`
- **应用**：当进程卡住或性能差时，用 strace 看它正在做什么系统调用（如读写文件、网络等待）。
