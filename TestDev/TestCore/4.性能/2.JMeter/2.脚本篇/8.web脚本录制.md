## 什么是脚本录制

- **定义**：用代理方式"录"下浏览器操作，JMeter 自动把每个请求转成 HTTP 取样器，不用手写脚本。
- **原理**：JMeter 启动一个代理服务器(HTTP(S) Test Script Recorder)，浏览器请求先经过它，被拦截并记录成脚本。
- **适用**：业务流程复杂、手写容易漏请求；快速产出脚本初稿。
- **测开**：录制 = 起步手段，录出来的只是"初稿"，必须二次加工才能用于压测。

## 录制方案

- **JMeter 内置代理**：HTTP(S) Test Script Recorder，本课主学。
- **外置工具**：Badboy(早期经典，了解即可)、BlazeMeter 浏览器插件(录制后导入 JMeter)。

## 录制步骤(JMeter 内置代理)

- **① 准备工作**
  - 测试计划下添加线程组(录制内容的目标存放位置)
- **② 启动记录器**
  - 线程组 → 添加 → 非测试元件 → HTTP(S) 测试脚本记录器
  - 端口填 `8888`(默认)，"目标控制器"选线程组
  - 点击启动，JMeter 提示代理已开启
- **③ 配置浏览器代理**
  - Chrome：设置代理指向 `localhost:8888`(或装 SwitchyOmega 插件切换)
  - 录制 HTTPS 页面需先安装 JMeter 证书：`jmeter/bin` 下 `ApacheJMeterTemporaryRootCA.crt`，双击导入并信任
- **④ 开始录制**
  - 浏览器里手动操作业务流程(登录 → 查询 → 下单等)
  - 操作完回 JMeter 点停止
- **⑤ 查看结果**
  - 线程组下自动生成一串 HTTP 请求，就是录制产物

## 录制后处理(必做，重点)

- **清理静态资源**：删除 CSS/JS/图片等请求(可用"排除模式"过滤 `.css .js .png .jpg`)，否则压测打的全是静态文件。
- **参数化**：账号、搜索词、订单量等写死的值改 `${变量}`(CSV/函数)，否则所有用户同一份数据。
- **关联**：token、session 等动态值做提取引用，否则第二个请求必失败。
- **补断言**：录制不带断言，手动加响应断言/JSON 断言。
- **整理优化**：重命名请求(可读性)、删除重复/无关请求、加注释。
- **面试话术**：录制脚本直接跑压测必翻车——静态资源占流量、数据写死、动态值不关联，错误率 100% 都正常。

## 录制注意事项

- **HTTPS 报错**：证书未信任导致，装 JMeter 根证书即可。
- **代理串台**：录完记得关闭代理/记录器，否则浏览器无法正常上网。
- **动态值必关联**：录制出来的是"这一次"的固定值，不代表下一次。
- **适用边界**：登录态、验证码、websocket 等场景录制效果差，优先手写。

## 测开视角

- 正经压测脚本 = 录制起手 + 手写精调：录制拿全请求清单，再人工参数化/关联/清理。
- 录制的价值是"不遗漏接口"，不是"免写脚本"。
- 对应代码：录制 ≈ 抓包工具(Fiddler/Charles)的请求记录，最终都要转成可维护的脚本。

## 面试高频题

- **Q**：JMeter 怎么录制脚本？**A**：加 HTTP(S) 测试脚本记录器，设端口 8888，浏览器代理指向 localhost:8888，操作业务流程后停止，请求自动生成。
- **Q**：录制 HTTPS 请求报错怎么办？**A**：导入并信任 JMeter 根证书(ApacheJMeterTemporaryRootCA.crt)，配置浏览器代理后重录。
- **Q**：录制完的脚本能直接压测吗？**A**：不能。必须清理静态资源请求、参数化写死的值、关联动态值、补断言，否则错误率全假。
- **Q**：录制和手写脚本怎么选？**A**：复杂流程用录制快速起稿，核心场景手写精调；录制产物按"清理 → 参数化 → 关联 → 断言"四步改造。
