## Linux
- **Linux 在测试中的用途**：
  1. 部署测试环境（搭服务、启应用）
  2. **通过查看日志定位问题**（tail grep）
  3. 操作数据库进行数据校验或者数据准备（连到 DB 服务器执行 SQL）
  4. 监控服务器性能指标（CPU、内存、磁盘、网络）

- **环境部署**
  - 具体工作内容：搭建测试环境、部署被测服务、配置中间件
  - 涉及命令/工具：`tar`, `rpm`, `yum`, `systemctl`
  - **面试话术示例**：“我负责搭建测试环境，用Docker+docker-compose一键部署整套服务，避免环境不一致问题。”
- **日志分析**
  - 具体工作内容：定位Bug、排查异常、监控错误
  - 涉及命令/工具：`tail`, `grep`, `awk`, `sed`, `less`
  - **面试话术示例**：“有一次线上问题，我通过`grep`和`awk`分析日志，5分钟内定位到是某个接口空指针，开发看了日志直接修复。”
- **数据操作**
  - 具体工作内容：连接数据库、准备测试数据、结果校验
  - 涉及命令/工具：`mysql`, `redis-cli`, `mongo`
  - **面试话术示例**：“我写了一个shell脚本，自动向数据库插入测试数据，并清理过期数据，集成到CI中每天运行。”
- **性能监控**
  - 具体工作内容：分析系统资源瓶颈
  - 涉及命令/工具：`top`, `free`, `df`, `iostat`, `netstat`
  - **面试话术示例**：“压测时我发现CPU飙高，用`top`找到进程，再用`strace`追踪系统调用，发现是日志刷盘太频繁，优化后TPS提升30%。”
- **脚本编写**
  - 具体工作内容：自动化日志分析、数据清理、监控报警
  - 涉及命令/工具：`shell`, `crontab`
  - **面试话术示例**：“我写了一个日志监控脚本，当错误率超过阈值时自动告警，并收集上下文日志，节省了手工排查时间。”


## 文件系统及主要目录介绍

### 文件系统基本概念
- Linux 采用树状结构组织文件系统，所有路径都从**根目录/**开始。
- Linux **一切皆文件**

### 常见目录

- **/**
  - 作用：根目录，一切从这里开始
  - 测试场景举例：所有路径的起点，**绝对路径 vs 相对路径**
- **/home**
  - 作用：普通用户的家目录
  - 测试场景举例：多用户环境下，每个用户独立空间，**权限隔离**的体现
- **/root**
  - 作用：管理员的家目录
  - 测试场景举例：配环境时常用。**提问**：为什么 root 的家目录不在 /home？(答：为了系统修复时也能访问)
- **/usr**
  - 作用：存放用户安装的软件和共享文件
  - 测试场景举例：**重点关注**：`/usr/local` 是源码编译安装的默认位置，常在这装工具
- **/etc**
  - 作用：系统配置文件
  - 测试场景举例：**重中之重**：nginx.conf、redis.conf、hosts、profile，提问“你改过哪些配置文件？”回答：改nginx.conf后没reload导致配置不生效；改hosts后没刷新DNS缓存。
- **/bin**
  - 作用：常用命令（ls、cp 等）
  - 测试场景举例：`/sbin` 是管理员命令，普通用户不能用，体现权限设计
- **/var**
  - 作用：变化的数据，尤其是日志 **/var/log/**
  - 测试场景举例：messages、secure、应用日志都在这里，**tail -f** 是调试神器。“日志文件太大怎么办？” 回答：用`logrotate`配置日志轮转；写脚本定时清理；分析哪些日志可以降级。
- **/tmp**
  - 作用：临时文件（重启会清空）
  - 测试场景举例：放临时测试数据；“/tmp目录下的文件会被自动清理吗？” 有些系统重启清空，有些定时清理（如systemd的`tmpfiles.d`）。不适合放重要数据。
- **/opt**
  - 作用：可选的应用软件包
  - 测试场景举例：Jenkins、Tomcat 常在这
- **/proc**
  - 作用：虚拟文件系统，进程和内核信息
  - 测试场景举例：**装逼必备**：`cat /proc/cpuinfo` 看CPU，`/proc/meminfo` 看内存，**实时动态**；更常用`top`、`htop`
- **/dev**
  - 作用：设备文件
  - 测试场景举例：挂载磁盘时会涉及
- **/mnt**
  - 作用：临时挂载点
  - 测试场景举例：挂载共享目录
- **/boot**
  - 作用：内核相关文件
  - 测试场景举例：一般不碰
- **/sys**
  - 作用：内核和硬件信息，类似/proc但更结构化
  - 测试场景举例：查看硬件状态、修改内核参数（如网络调优）


- **Q**：如果 nginx 启动失败，你会去哪些目录排查？**A**：先看 `/var/log/nginx/error.log`，再看 `/etc/nginx/nginx.conf` 配置是否正确，最后用 `netstat -anpt | grep 80` 检查端口占用。

## 远程连接

### 连接条件
- **IP 确认**：`ifconfig` 或 `ip addr`，需要本端可以 ping 通对方 ip
  - `hostname -I | awk '{print $1}'`（动态获取本机 IP）
- **端口确认**：
  - `netstat -anpt | grep ssh`（ssh 端口默认 22，需要被控端开启 SSH 服务）
  - `ss -anpt | grep ssh`
- **SSH 服务**：服务名是 `sshd`，启停命令：
  - `systemctl status sshd`（查看状态）
  - `systemctl start/stop/restart sshd`（启动 / 停止 / 重启）

### 免密登录配置
- 本地生成密钥：`ssh-keygen -t rsa`
- 复制公钥到远程：`ssh-copy-id user@remote_ip`
